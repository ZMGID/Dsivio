# 视频工作台

核对日期：2026-09-10，按当前工作区实现记录，不代表已发布版本。

入口：`#chat/videos`。沿用全局主题、Button / IconButton、Select、输入框与滚动条。

视频创作：素材与要求 → 选择提示词助手（不选则默认通用视频）→ 编写方案 → 用户确认 → 点击生成 → 查询与本地成片。三条路线均使用确认后的提示词原文，不再调用第二个模型改写。报价仅供参考，不是提交前置条件。
已有提示词：在“这次要拍什么”填写原文，点击“使用原提示词生成”，跳过导演和模型提示词转换，直接进入生成页查看规格/报价并提交。Grok、MiniMax、ComfyUI 均保留原文和换行；素材与要求页的操作栏位于内容底部，不随滚动悬浮。
参考分析：单条视频链接或本地视频 → video-analyzer MCP → Agent 根据关键帧、转写和时间线拆解 → 用户确认并保存参考模板。
模板库：区别成片验证模板和未验证的参考拆解模板。内置上游已有的 15 秒卧室 UGC 模板，不伪造示例视频。

## 共用能力

- `src-tauri/resources/plugins/dsvideo-plugin` 保留原插件六个 Skill、两个 MCP 和生成脚本。来源版本记录于 `STUDIO.md`。
- 启动时注册为内置包，沿用现有插件发现和启用机制。保留用户启用状态，应用更新覆盖包内容，用户数据独立保存。
- `scripts/studio.py` 是聊天和 UI 共用的工作区服务。使用 JSON stdin/stdout、跨进程锁、原子写入和乐观版本检查。
- 任务、素材、模板、结果：应用数据目录的 `video-studio`。API 配置仍使用原插件的 `dsvideo/providers.json`。
- 助手编写和修改提示词复用应用 Agent loop，只使用所选助手的提示词与模型，不加载旧导演技能或外部工具；生成通过原 Python 客户端及现有 MCP 连接池执行。
- Comfy MCP、视频分析 MCP、独立 Python / Node、FFmpeg / ffprobe 和 yt-dlp 随应用打包，启动使用应用资源绝对路径，不运行 npx 或现场安装依赖。ComfyUI 服务端与 H3 工作流节点仍由用户部署。

## 内置运行环境构建

构建机需要 Node.js、Rust 和 uv（发布流水线自动准备）。`npm run build:video-runtime` 按 `scripts/video-runtime` 中的版本、npm lockfile 和带哈希的 Python 依赖锁文件生成 `src-tauri/resources/video-runtime`。生成目录不提交到 Git，Tauri 开发启动及打包前自动准备。

支持 macOS Apple Silicon 和 Windows x64，须在目标平台构建。Node 下载校验固定 SHA-256；独立 Python 由 uv 下载。构建时安装依赖，用户机器只运行已打包文件。发行包保留各依赖的许可证和包元数据。

`npm run verify:video-runtime` 在隔离的 PATH 和空 npm 缓存下检查 Python 工作区、Comfy CLI、yt-dlp、两个 MCP 的握手以及本地视频元数据读取。构建流程另会移动整个运行目录到带空格的新路径，验证可搬移性。生成或读取本地测试视频不调用付费 API 或 ComfyUI 服务端。

应用启动时刷新内置 MCP 的启动路径，迁移旧 npx / 系统 Python 配置，并保留用户的服务启用开关和工具选择。MCP 所属包停用时仍由统一资格检查拦截。运行环境作为独立资源打包，不复制进通用插件导入目录。

## 生成与恢复

路线无默认值；禁止失败后自动切换。编辑任务会清除剧本确认、提示词和报价。
报价记录查询时间、配置版本和模型，供用户参考；缺少报价、报价失败或旧报价不阻塞提交。提交前先持久化状态，获得远程编号后立即保存。
提交超时且无可靠回执时进入待核查状态，不能重复提交；用户可从供应商控制台核实后补录编号。
查询只访问原任务地址和编号。Grok 下载后使用 ffprobe 检查成片；MiniMax 当前没有同等的本地规格检查。ComfyUI 在成功或失败后尝试释放空闲模型，队列有任务时跳过。

当前 UI 可显示 MiniMax / Grok 模型目录中的官方参考报价；自定义网关的实际费用由供应商决定，不将参考价当作实际账单。原插件的高级 API 参数仍可在聊天使用。
API Key 不返回前端或写入任务和模板。结果大于 80 MB 时使用本地播放器打开。
浏览器环境只预览布局，真实执行需桌面应用、已配置的视觉聊天模型以及所选路线依赖。

## Grok 请求与成片校验

- `approve` 将当前 `script` 原文写入 `prompt`；`prepare`、`quote` 和 `submit` 保持同一规则，不调用模型另写英文版提示词。导演规划会提示已实测服务的长度约束，但用户文本没有本地全局长度硬限制，也不静默截断。
- 请求由 `scripts/studio.py::request` 构造，提交 `model`、`prompt`、`duration`、`aspect_ratio`、`resolution`、`generate_audio` 以及相应素材。`speechMode=auto` 保留剧本声音设计；只有明确 `silent` 才关闭生成音频。
- 单图首帧在提交前等比缩放、补白到请求画幅；不拉伸商品，不在生成后修改尺寸来冒充达标输出。参考生成仍受本地接口适配器的 720p 上限约束。
- 下载后记录 `media.width/height/duration/hasAudio`。当前判定容差：画幅相对偏差不超过 2%，短边不低于请求分辨率减 32 像素，时长偏差不超过 0.25 秒；要求有声时必须存在音轨。检测失败或规格不符标记 `failed`，保留成片与远程编号，不自动再次付费生成。
- 自动检查音轨存在性，不能证明音量足够、对白正确或语音清晰。实际验收还需检查音量和内容；没有转写不代表没有声音。
- [2026-09-10 长度调查](audits/grok-prompt-length-2026-09-10/README.md)记录了特定网关的 4096 UTF-8 字节边界，不能外推为所有 Grok 服务的限制。错误保留供应商信息，并记录字符数、UTF-8 字节数和服务主机。较短文本成功不等于原剧本已获支持。

## 任务编辑与恢复

- `videoValidation.ts` 在规划、分析、确认和提交前给出素材、画幅、清晰度、时长、路线配置错误。Rust 的规划/准备入口先调用 worker `preflight`；worker 再检查版本、运行状态、素材和配置，避免先消耗模型调用再发现输入不可用。
- 视频创作、参考分析、参考仿拍分别保存草稿；已有任务的未保存编辑还按任务 ID 保留本地副本。切换任务后异步结果只更新对应任务，不能覆盖新打开的任务。
- 已完成任务可修改需求或剧本并重新确认生成。同一任务生成写入 `outputs/<任务ID>/video.mp4`；重新生成完成后替换该路径的成片，不提供图片工作台式的成片版本库。
- 任务列表共用搜索、状态筛选、排序、钉住、定位文件和删除。删除会明确确认永久清理范围；`running/submitting/uncertain` 及被 worker 锁定的任务不能删除。详情见[聊天与工作台互通](studio-chat-sync.md)。

## 流程简化（2026-09-09）

新增参考仿拍入口：参考视频与商品一起输入，确认拆解后直接进入创作，参考结构作为任务模板传递。普通拆解仍可独立保存模板。
分析 Agent 输入包含用户分析重点、报告语言与工具证据。宽泛创作支持 `concepts` 三拍法结果；选择后通过 `selectedConcept` 继续生成剧本。空剧本不能批准或提交。
视频页面各入口的未提交草稿独立保存在本机浏览器存储。正式执行前进入共享 Python 任务服务。当前方案确认后，所有路线直接使用原提示词；报价查询失败不阻塞点击生成。
已知运行任务自动查询最新 revision 和远程状态，不确定提交不自动重提。默认声音为 auto，按请求或参考设计；语言不再硬编码为巴西葡萄牙语。


## 视频提示词助手（2026-09-10）

助手中心新增“视频生成”分组，内置通用视频（默认）、电商产品展示、电商 UGC 口播。自建或复制的助手也可选此分组。视频页只列出该组未归档助手；内置助手无需先加入聊天应用即可选择。

`VideoBrief.assistantId` 随草稿和任务保存；新任务沿用最近主动选择的助手。服务/分辨率修改不会覆盖助手偏好。空值使用默认助手；显式选中的助手若删除、归档或移出分组，规划会提示重新选择，不静默更换。直接使用原提示词不依赖助手是否存在。

规划与修改都读取助手中心当前保存的 system prompt 和模型；空模型配置沿用当前聊天模型。传入用户要求、参数、模板与参考图片（含显式首尾帧）；本地参考视频/音频路径不当作已分析证据。JSON 输出协议仅承载 script/concepts，不再叠加固定四镜、语言、场景等导演模板。

v10 启动迁移只更新旧内置视频助手并新增两个电商视频助手，保留其模型、安装/归档状态及其他助手。确认后的 `prepare` 只保存原文；原提示词入口也不会调用规划或修改助手。
