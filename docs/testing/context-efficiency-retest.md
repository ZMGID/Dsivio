# 上下文效率复测清单（#51）

本清单不自动启动付费模型任务，也不操作其它 Agent 的进程或目录。

## 确定性验收

- `native_file_receipts_are_short_on_the_wire_and_keep_review_diff`：真实临时文件、内置 write/edit 与本地 HTTP 模型服务。检查下一轮实际 JSON 请求的工具结果不含代码正文，结构化记录仍保留完整 diff，最终文件正确。
- `distant_local_edits_preserve_large_file_diff`：1303 行中文 CRLF，六处跨区域替换后1313行，1283行不变，+30/-20、六个 hunk。
- `diff_budget_exhaustion_reports_unknown_counts_without_changing_write_result`：计算超限不影响文件落盘，明确 `diff_complete=false`，不显示伪精确增删数。
- `stale_write_snapshot_does_not_overwrite_external_changes`：旧内容失效时保留外部修改。应用内路径锁和替换前内容校验共同使用；跨进程校验为乐观并发检查，不声称能锁住不合作的外部写入者。Windows 使用原子替换，去除先删除旧文件的空档。
- `measured_view_survives_append_and_reopen_but_rejects_configuration_or_history_changes`：请求来源可持久化，追加消息仍适用；模型、提供方、协议、系统指令、工具及 schema、历史前缀变化使旧值失效。无法证明等价的任意请求体覆盖诚实回退估算。
- `run_loop_reserves_output_and_does_not_send_an_unfixable_prompt`：小窗口加大输出预留，固定上下文已超预算时不发送模型请求。
- 长日志检查：全文路径可读取；单行大输出、多行输出都只返回有限首尾，保留退出状态。目录默认40条样本，并返回总数量。

## 三方隔离复测

启动前只检查已分配端口与对应进程，发生冲突则另选空闲端口；不终止其它任务服务。结束后仅验证和清理登记的本次临时路径，不枚举整个共享 Temp 来猜测归属。

分别记录最后一次实报输入/输出、缓存命中、累计输入/输出、工具结果字节/字符、调用次数、失败重试、用时和题目验收结果。没有实报时明确写“估算”。记录首次创建、局部编辑、必要整份重构和返工原因；不能把每次 write 算成浪费。

相邻请求 token 差额包含协议封装及其它消息变化，不能将组间差额当作保证节省量。相同模型配置和任务验收标准下比较最终成果；不能通过降低 high、省略必要推理回放或提前有损压缩来凑170K。

## 预算依据与兼容性

[Gemini Models API](https://ai.google.dev/api/models) 分别提供 inputTokenLimit 和 outputTokenLimit；因此 Gemini 的输入额度不再次扣除输出。其它内置适配器按共享上下文为有效输出留空间。[Claude 上下文说明](https://platform.claude.com/docs/en/build-with-claude/context-windows) 指出新型号可能接受输入加 max_tokens 超窗的请求，但这仍可能使输出在窗口边界停止；本地预算保留完整回答空间。

模型覆盖新增可选 `maxInput`。旧配置无此字段时保持可加载；未知模型使用现有后备窗口并标示估算，不自动将新型号限额套到旧别名。旧消息无请求身份时不伪造来源；旧文件 diff 无完整性字段时保留旧记录，不补写“已验证”。

## 工具参数优化补充（2026-09-14）

目的：减少后续请求重复携带已经落盘的大段代码。首次实际执行仍接收完整参数；不会通过省略待执行代码来节省用量。

- 仅处理内置 `write` / `edit`，要求成功记录、成功结构化结果、调用与结果配对，以及参数与审阅记录一致。MCP、失败、取消、无配对、签名或原生推理项的调用保留原文。
- 最新 assistant 批次完整保留用于即时验证；更早的调用参数达到8KiB时，只精简其中至少1KiB的正文字符串。路径、调用ID、工具名和其余字段保留；省略处明确标出字节数、SHA256及重新读取文件的说明。
- 本地审阅参数、原始 API 消息、运行检查点保持完整。发送历史发生变化时重新验证实报适用性，不能继续使用缩减前的计数。
- `write` / `edit` 描述去除重复说明，并要求最小且唯一的匹配片段，避免把无关代码放入局部编辑参数。
- 实际 HTTP 回归：2000行文件写入后再局部编辑，较早写入调用的回放参数小于1000字节；最终文件与完整审阅数据正确。重新加载会话覆盖 write/edit 共18组成功及保护条件。

这是明确的历史发送视图精简，会失去模型直接引用旧正文的能力；需要具体代码时重新读文件。不是无损token压缩，也不承诺每种模型/协议都有相同收益。

补充验收完成：实际请求精简、会话重载、检查点原文保护和重复调用ID测试通过。检查点与重复ID问题均先通过失败测试复现，再修复；同ID历史保留原文，不参与精简。最终Rust全量2396通过、2失败、45忽略，失败仍是上文两个未修改的Windows路径断言；TypeScript类型检查通过。Standards与Spec最终复审均无剩余发现。

## 问题1复测中断：图片消息打断工具批次（2026-09-14）

实际故障：该次运行记录91次工具调用后，下一次planning请求收到400 `No tool output found for tool call ...`，转入recovered兜底回答，未正常完成任务。对应bash结果在本地历史中存在，问题不是工具未执行。

最小触发顺序：assistant同时请求read和bash → read结果 → read附带的user图片消息 → bash结果。严格接口在图片/user边界校验时，第二个结果尚未出现。原有单工具图片测试无法捕获这个多工具场景。

修复：统一请求组装将该批全部tool结果放在附带user消息之前；不更改完整本地审阅历史、不删除结果、不伪造缺失结果、不跨新assistant批次搬动消息。适用于新运行，也适用于已存下来的交错历史。

- `image_followup_never_interrupts_a_multi_tool_batch_on_the_wire`：本地HTTP模型服务、两个实际执行器调用、Responses最终请求顺序；先红后绿。
- `captured_history_replays_complete_tool_batches`：显式设置`KIVIO_TOOL_ORDER_REPLAY`后离线读取会话，经过真实请求构造检查所有tool配对与结果数量。默认忽略，不需要网络，不执行历史工具命令。

验证结果：真实失败会话177条内部消息的离线请求回放通过；多工具图片HTTP回归通过。Rust全量2397通过、2个原有路径断言失败、46忽略；捕获回放用例显式启用后单独通过。双轴复审均0发现。桌面开发版已重新编译启动。未自动重跑付费问题1，也未将测试通过表述为整题已完成。

## 上下文面板优先实报（2026-09-14）

用户复测会话已经保存输入238983、输出476、总量239459，但刷新面板将它替换为219253的字符估算。原因是显示路径复用了请求预算的完整指纹校验；重建请求不一致会丢弃已返回的计数。

显示路径直接使用最近assistant的单次`anchor_usage`，只估算后续新增消息，不使用累计账单`usage`，不要求重建请求指纹。没有实报、实报对应内容已被编辑、清空或压缩时才回落整体估算。下一次请求的内部预算仍独立检查适用性。

`display_usage_prefers_report_without_requiring_a_rebuilt_request`覆盖实报优先、无指纹的旧实报、增量估算及编辑/清空/压缩失效。`captured_context_display_uses_returned_usage`使用`KIVIO_CONTEXT_REPLAY`指定本地会话进行离线回归，不调用模型或执行历史工具。

旧数据缺少协议来源且存在缓存计数时无法区分缓存是否已包含在input内，此时才兜底；有协议记录的实报不随当前供应商切换而改变口径。真实样本回放先失败、修复后通过，实报239459。Rust全量2398通过、2个原有路径断言失败、47忽略；上下文前端16项与TypeScript类型检查通过；双轴复审0剩余发现。
