# 图片与视频：提交梳理、删减和无浏览器调试

基线：`9710f8f`。本轮只使用 Git、源码、单元/组件测试、Python 客户端、MCP stdio、HTTP 和 FFmpeg，没有浏览器调试或 Computer Use。

## 结论

图片部分已经不只是 dsimage 的界面拆分：它重新实现了协议、任务格式、素材准备、规划、模板和样品状态机。视频部分更接近合理的插件封装，实际生成仍调用 dsvideo 的 Python 客户端，但外层页面与服务叠加了轮询、草稿和锁，造成额外故障。

本轮修复明确的调用/状态缺陷，删除无引用样式和重复轮询。没有将整个图片工作台迁移回 dsimage，也没有声称所有路线和桌面交互已通过端到端验证。

## 实际调用链

| 入口 | 调用链 | 重复/风险 |
| --- | --- | --- |
| 图片页面 | `ImageStudio` → Tauri image_studio → preparation / agent / workflow → engine.rs → 图片 HTTP | Rust 重新实现了 dsimage 的生成协议和结果解析 |
| 内置 dsimage 脚本 | dsimage.py / core.py → gen_image.py → 图片 HTTP | 共用配置和模板，但 `_dsimage/batch.json` 不等于页面 `tasks/*.json` |
| 聊天普通生图 | chat direct_image → chat/image_generation.rs → 图片 HTTP | 第三套适配路径，路由、参数和返回格式支持又不同 |
| 视频页面/工作台工具 | video_studio.rs → dsvideo scripts/studio.py → Grok/MiniMax 客户端；Comfy 经 MCP | 已共用插件客户端，应该继续收薄外围，而非再写一个视频执行器 |

图片一次“开始”还可能先识别每个商品、生成模板、派生素材、质检，再写提示词和生图。那些步骤各自需要远程调用，远超“把插件功能拆成界面”的必要成本。不能把“后台自动做”视为已经简化底层。

## 本轮修复

| 问题 | 触发与影响 | 改动 |
| --- | --- | --- |
| 图片插件地址不同于桌面 | 供应商只填域名时，Rust 请求 `/v1/images/edits`，内置 dsimage 请求 `/images/edits` | 插件配置桥接统一补 `/v1`；保留明确的 `/v1beta` 或代理路径 |
| 异步图片完成却取不到结果 | dsimage 的响应是 `data.result.images[0].url[0]`，Rust 只接受 url 字符串 | 支持数组地址，并保留既有同步/兼容格式 |
| 保存设置改坏接口协议 | 每次保存都重新推断协议；既有 async 配置可能被重置 | 仅在更换模型时推断；普通保存保留草稿协议，补 apimart 检测 |
| 自动刷新覆盖未保存输入 | 已有任务的远程版本改变时，图片/视频刷新直接覆盖本地 brief；图片也会覆盖正在修改的 plans | 只有本地无编辑且不忙时才自动接收正式任务更新 |
| 视频进度双重实现 | 当前任务在组件内轮询，其他任务又由 hook 轮询；切换时职责转移复杂 | 所有运行任务统一走 `useVideoTaskProgress`，保留显式恢复按钮 |
| 单个视频请求堵住整个工作区 | Python 在全局锁内执行长 HTTP；bootstrap、其他任务和设置也等同一把锁 | 按任务加锁；同任务仍串行，不同任务与工作区读取独立 |
| ComfyUI 重拍取回旧视频 | 所有输出进入同一目录，再用 read_dir 取第一个视频 | 输出按远程任务编号隔离，并验证编号可用于路径 |
| ComfyUI 错误原因被吞 | Rust 的 `Err(_)` 丢弃上传/工作流错误，只存通用文案 | 保留限长、脱敏后的具体错误，同时维持未提交/提交不确定两种状态 |
| 样式文件大小写不匹配 | 视频引用 `ImageStudio.css`，实际文件为 `imageStudio.css` | 修正大小写，避免在区分大小写的文件系统构建失败 |

## 已删除的冗余

- 54 条无组件引用的图片/视频 CSS 规则，及无人使用的旋转动画和空媒体查询，共 290 行。对应旧任务卡、旧素材条、旧规格页脚、旧进度条和旧 toast。通过全 src TS/TSX 引用扫描，并检查动态类名用法后删除。
- 视频当前任务的独立轮询 effect；当前任务与后台任务使用同一个有并发上限的轮询器。
- 图片配置保存时的第二次协议推断。

没有删除原图、用户任务、模板、历史版本或内置运行环境。没有做改文件名/拆组件式的“表面减量”。

## 后续大幅删减的具体边界

最大收益应来自统一执行合同，而不是继续加自动修复页面：

1. 图片只保留一套 dsimage 生成适配器。把配置、明确的 submit/poll、结果与远程编号作为稳定合同，再让 Rust 做任务持久化和桌面文件适配。迁移时保留已受理异步编号，不将恢复查询变成重新生成。
2. 清楚区分 gen、replace、smart；制作模板是模板操作，不应再发展成第二套商品生产状态机。先证明与原插件行为一致，再迁移已有 workflow/design 任务；不能直接删掉旧任务的读取与恢复路径。
3. 正式任务由服务端持有；页面只保存未提交表单。逐步移除 localStorage、共享草稿、任务对象之间的全量双向同步，保留明确的任务引用与版本检查。
4. 视频保留现有 dsvideo 客户端和 workspace，继续缩减 React 操作编排。不要再为相同路线添加新的 Rust HTTP 适配器。

这些是后续迁移范围，本轮没有假装已完成整体架构替换。
