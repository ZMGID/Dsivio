# 图片与视频可靠性修复（2026-09-10）

## 已定位并修复

- 视频 worker 的返回值包含任务字段 `error`。宿主误把任何字符串（包括成功任务里的空字符串）当作接口错误，导致成片打开、预览、保存、失败恢复均可能中断。现在区分任务对象和独立错误响应。
- 单张商品图在自动模式下使用 Grok `reference_images`，只有明确 `inputMode: image` 才驱动首帧。参考模式继续验证清晰度与素材限制。保留工作区此前已有的原剧本直传和参数校验修复。
- 新任务保存并继承生成服务、每个服务各自的清晰度；切换素材模式不再无条件清空清晰度。图片新任务继承画幅和清晰度。内容和首帧模式不带入新任务。
- 视频预览不再因任务 revision 更新清空，文件按钮与元信息刷新不会重建播放器；预览失败显示真实错误。macOS 文件打开现在检查命令退出结果。
- 普通单图原始要求直接生成，不再经由规划模型改写成另一套描述。参考图顺序、用户额外风格与商品信息保留，语言设置本身不要求新增文案。套图继续按模板规划。局部改图的修改要求优先于旧方案。
- 视频导演和要求优化入口不再默认套完整导演报告、强制镜头数量、复述复杂图案、猜测商品机理。内置聊天指南与页面规则同步。
- 本机 `target/debug` 的 Python 副本可通过签名检查但启动收到 SIGKILL；资源目录中的同版本 Python 正常。普通开发版改用稳定的源码资源目录，安装包仍使用自己的打包资源。
