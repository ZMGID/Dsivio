# dsivio 应用市场：前端开发交接文档 v1

编写日期：2026-09-18。

本文可以直接交给前端开发者，包含产品背景、页面结构、交互、状态、数据边界和验收要求。无需阅读之前的讨论即可开始。

**当前状态：已完成 Package 内容规范及空白模板，市场页面、加载开关、市场安装接口和聊天包绑定尚未实现。本文中的新接口均为拟定协作契约，不代表已有可调用的后端。**

## 1. 产品目标与使用者

dsivio 是给内部员工使用的桌面软件。员工主要做跨境电商，图片与视频生产较多，不熟悉 Skill、MCP、插件或运行环境。

维护者负责跑通流程、验证适配性，将完整能力作为 package 发布到 GitHub。一个 package 可以包含多个 Skill、MCP、插件、脚本和模板。员工在软件中看到的是能解决具体问题的“应用”，如“商品套图”“参考视频仿拍”。

核心体验：**找到功能 → 看懂示例 → 安装一次 → 在对话中使用 → 拿到结果。**

常用应用可以保持加载，员工以后直接聊天，或从输入框旁选择，无需每次回市场。

### 1.1 已确定的产品要求

- 有独立的“应用市场”页面，按用途分类，由维护者持续补充内容。
- 内容从 GitHub 在线获取，不塞进 dsivio 安装包。
- 每张卡片可以点开，详情通过简短的对话气泡和成品示例讲清楚怎么用。
- 安装由聊天 Agent 按维护者编写的 MD 文档执行，包含配置及验收。
- 每个已安装应用有加载开关，卡片上直接看到“已加载／未加载”。
- 加载偏好跨重启保留；常用应用在普通对话中可用。
- 实际使用都进入现有聊天系统，沿用附件、消息、成品预览和历史记录。
- 界面简短、直接，默认不向员工展示技术组件和环境细节。

### 1.2 本文采用的实现默认值

以下是为第一版落地确定的默认交互，可在实现中微调尺寸与布局，不应改变上述产品行为：

- 页面名称“应用市场”，聊天入口名称“应用”。
- 详情采用市场内的独立详情页，返回后保留列表状态。
- 首次安装验收成功后默认加载，手动关闭后保留选择。
- 市场“使用”创建新工作对话；聊天菜单选择应用用于当前对话。
- 第一版显式选择一个应用作为当前工作入口；应用内部多个能力由包管理，不做员工手动编排界面。

## 2. 第一版交付范围

| 必须做 | 说明 |
| --- | --- |
| 市场列表 | 分类、搜索、已安装筛选、卡片、刷新、缓存及空状态 |
| 应用详情 | 简短说明、示例对话、媒体展示、条件提示和主操作 |
| 加载开关 | 卡片、详情、聊天菜单共享同一真实状态 |
| 安装反馈 | 真实阶段、待配置、失败继续、完成反馈，复用安装对话 |
| 聊天应用菜单 | 查看已安装应用，加载／关闭，选择当前使用的应用 |
| 对话绑定展示 | 当前应用名称、版本说明、材料引导、会话恢复 |
| 更新和修复入口 | 展示真实状态，保留可用旧版和加载偏好 |
| 卸载入口 | 放次级菜单，保留用户作品，处理运行中情况 |

第一版不做评分、评论、收藏体系、公开投稿、管理后台、工作流画布、复杂依赖图或多应用编排。加载开关已经承担“常用能力”的作用，暂不增加收藏按钮。

此次前端范围不包含删除原图片／视频工作台、迁移其历史任务、重写 Skill／MCP 设置页。新入口的增加不能破坏这些现有功能。

## 3. 面向员工的用词

| 员工看到 | 内部含义 |
| --- | --- |
| 应用 | 一个 market package |
| 安装 | 下载、配置、注册组件并验收 |
| 已加载 | 已加入日常对话的可用能力目录 |
| 未加载 | 安装内容保留，但普通对话不会发现或调用 |
| 当前使用：商品视频 | 当前对话已绑定该应用的工作指令与能力 |
| 需配置／需修复 | 运行条件不足，需要一个明确的下一步动作 |

不要把“已安装”“已加载”“当前使用”合成一个布尔值。已加载不代表所有提示词进入上下文，也不代表 MCP 常驻；这些实现细节不需要员工理解。

技术词仅在折叠的“详细信息”中出现。员工默认页面不出现 commit SHA、MCP ID、依赖名称、安装命令、栈信息或原始 JSON。

## 4. 信息架构与路由

建议新增侧栏入口“应用市场”，与现有业务入口同级，不藏在设置里。

| 页面／入口 | 建议路径或位置 | 行为 |
| --- | --- | --- |
| 市场首页 | `#chat/market` | 分类列表 |
| 应用详情 | `#chat/market/<packageId>` | 可恢复的详情页 |
| 安装／修复对话 | 现有会话路由 | 标题如“安装应用 · 商品视频” |
| 工作对话 | 现有会话路由 | 标题如“商品视频 · 风扇” |
| 聊天应用菜单 | 输入框工具区 | 就地弹出，避免离开当前对话 |

市场页跳转时保留当前聊天草稿和附件。返回列表保留搜索词、分类、已安装筛选及滚动位置。进入未知包详情时显示“这个应用暂时无法查看”，提供“返回市场”，不能把包 ID 当作会话 ID。

建议使用列表状态对象记录浏览状态，安装过程由独立状态层持有，不能依赖市场页面是否挂载。

## 5. 市场首页

### 5.1 布局

```text
应用市场                                  [刷新]
经过团队验证，选择需要的功能，在对话中使用。

[ 搜索应用名称或用途                         ]
[全部] [图片] [视频] [其他]          [只看已安装]

┌───────────────────┐  ┌───────────────────┐
│ [图标] 商品套图     │  │ [图标] 商品视频     │
│ 根据商品图制作一套  │  │ 根据商品图片制作   │
│ 电商展示图片。      │  │ 简短的带货视频。   │
│ 图片               │  │ 视频               │
│ 已加载 [开关开]    │  │ 未安装             │
│             [使用]│  │             [安装]│
└───────────────────┘  └───────────────────┘
```

分类来自 catalog，不能在 UI 写死只有图片和视频。“全部”由界面生成，“只看已安装”是独立筛选条件，可与分类、搜索组合。

### 5.2 卡片规则

- 内容为默认图标、名称、简介、分类、状态、主操作和已安装应用的加载开关。
- 第一版 package.json 没有封面字段：使用按分类分配的默认图标。不要依赖未定义的 cover/icon 字段，也不要为了展示卡片要求作者额外制作封面。
- 名称最多展示两行，简介最多两行。完整内容在详情可见，不能让一张卡片被长文本撑得很高。
- 卡片信息区点击进入详情。按钮、开关、次级菜单不触发卡片导航；不要把整张卡片做成包含其他按钮的嵌套按钮。
- 主操作永远只有一个。更新提示和加载开关作为次要操作，卸载放“更多”菜单。
- 同一个应用的操作只锁定该应用，不让整个市场都不可点击。
- 初始按目录顺序展示；已安装筛选中包含已从市场下架但仍在本地的应用，标“已下架”，仍可查看本地说明和管理。

### 5.3 搜索与刷新

- 搜索名称、简介和分类名，不搜索安装脚本。
- 无需点击搜索按钮，输入后本地过滤已获取的目录信息。
- 先显示缓存，再后台刷新。刷新期间保留已有卡片，不整页闪白。
- 刷新失败有缓存：显示“暂时无法刷新，已显示上次内容”及重试入口。
- 刷新失败无缓存：显示错误状态与“重试”，不要显示成“没有应用”。
- 单个清单或示例损坏只影响该应用；可显示“暂时无法读取”，不隐藏所有正常条目。
- 不要求持续轮询 GitHub；进入页面与手动刷新即可满足 v1，后续由数据层按缓存策略优化。

### 5.4 空状态

| 情况 | 文案 | 操作 |
| --- | --- | --- |
| 目录真实为空 | 团队正在准备应用，发布后会显示在这里。 | 刷新 |
| 搜索无匹配 | 没有找到相关应用。 | 清空搜索 |
| 已安装筛选为空 | 还没有安装应用，先看看有哪些功能。 | 查看全部 |
| 当前分类为空 | 这个分类暂时没有应用。 | 查看全部 |

实际目录目前为空。开发示例数据必须明确标为演示，在正式构建中不能伪装成已发布应用。

## 6. 应用详情：用对话说明用途

### 6.1 信息顺序

```text
[返回应用市场]

商品视频
上传商品图片，制作适合目标市场的带货短视频。

使用示例
                         你：📎 商品图片
                             帮我做一个 15 秒的葡萄牙语视频。
AI：我会先准备脚本，确认后制作视频。
AI：[成品视频预览，点击播放]

需要配置视频服务，生成可能产生费用。

已加载 [开关]                              [使用]
详细信息 ▾
```

示例文字是产品说明，不代表已有真实可用视频包；开发演示应注明。

### 6.2 示例对话

- 读取包固定版本中的 example.json，2–6 条消息，优先三条。
- 沿用聊天的角色、气泡、附件视觉，但使用只读轻量组件；不需要消息编辑、重试、工具调用、复制菜单或模型状态。
- 明确标“使用示例”。不把示例追加到真实会话，不自动上传演示附件。
- 文字完整展示，遵守规范的短文本限制。保持内容自然高度，不逐条播放打字动画。
- 图片可点开大图；视频默认封面加播放按钮，用户点击才播放，不自动发声或预下载所有视频。
- 附件加载失败保留正文，显示“示例暂时无法加载”和局部重试，不影响查看说明或已安装应用的正常使用。
- 第一版对示例正文采用纯文本渲染即可，不需要任意 HTML。路径由数据层转换成受控资源 URL，组件不要直接拼接本机文件 URL。

### 6.3 条件与详细信息

notices 最多三条，以紧凑文字展示账号、费用或配置条件。实际需要什么就写什么，无条件时不显示空白占位。

折叠“详细信息”可展示当前安装版本、可更新版本、支持系统、最近验证日期。这里区分本机安装版本与市场最新版本，不能用新版的验证信息证明旧版已通过。

市场详情默认展示目录当前发布版本的介绍；已安装旧版时提示“当前使用 vX，可更新至 vY”。“使用”仍启动本机已就绪版本，新版不兼容不能阻止可用旧版启动。聊天应用菜单中的说明优先展示当前绑定或安装版本的本地内容。

安装／使用操作区在内容较长时保持容易找到，可以底部吸附，但必须留出内容安全间距，不遮挡最后一条消息或滚动条。

## 7. 状态与按钮：统一映射

状态映射应集中在一个纯函数或统一 view model 中，列表、详情和聊天菜单复用，不在三个组件分别判断。

| 实际情况 | 状态文案 | 主按钮 | 加载开关 |
| --- | --- | --- | --- |
| 未安装且可安装 | 未安装 | 安装 | 不显示 |
| 首次安装中 | 正在下载／正在配置／检查是否可用 | 查看进度 | 禁用或不显示 |
| 等待员工操作 | 需要补充配置 | 后端给出的下一步，如填写配置 | 禁用 |
| 首次安装失败 | 安装未完成 | 继续安装 | 禁用 |
| 就绪且未加载 | 未加载 | 加载并使用 | 关闭，可操作 |
| 就绪且加载完成 | 已加载 | 使用 | 打开，可操作 |
| 开关请求中 | 正在加载／正在关闭 | 暂时禁用 | 处理中，不接受重复点击 |
| 正在执行任务时关闭 | 本轮结束后停用 | 查看当前任务 | 显示关闭意图及待生效状态 |
| 环境失效 | 需修复 | 修复 | 不能显示健康的已加载状态 |
| 有新版，旧版可用 | 原加载状态 + 可更新 | 使用／加载并使用 | 按旧版实际状态 |
| 新版安装中，旧版仍可用 | 正在更新 + 旧版可用 | 使用旧版（仅后端允许时） | 可暂时禁用，偏好保留 |
| 更新失败，旧版仍可用 | 更新未完成，仍可使用旧版 | 使用旧版 | 按旧版实际状态 |
| 当前版本不支持本机且无可用旧版 | 暂不支持当前系统／需升级 dsivio | 不可用，说明原因 | 禁用 |
| 已从市场下架，本机仍可用 | 已下架 + 原加载状态 | 使用／加载并使用 | 可操作 |

“可更新”另提供小型次级操作“更新”，不要取代日常的“使用”按钮。更新失败时提供“重试更新”。运行中是否允许启动旧版、修复或卸载，由后端返回的动作能力决定，前端不猜。

开关失败回到后端确认的有效状态，并显示短错误。不得先显示成功后用后台报错掩盖真实失败。市场、详情和聊天菜单收到同一个状态更新后同步刷新。

## 8. 安装、配置和修复流程

### 8.1 首次安装

1. 员工点击“安装”，该应用立即进入提交中，防止双击重复请求。
2. 后端锁定要安装的包版本、下载内容，并创建或恢复安装会话；前端跳转返回的会话 ID。
3. 聊天中展示安装任务和紧凑进度卡，阶段为“正在下载 → 正在配置 → 检查是否可用”。
4. Agent 按 INSTALL.md 执行。若需要员工登录或填写配置，给出一个明确动作。
5. INSTALL.md 中的必需检查都通过，后端报告就绪并完成默认加载；进度卡显示“安装完成，可以使用了”和“开始使用”。
6. 点击开始使用，创建正式工作对话。不要把整段安装日志变成工作对话的历史上下文。

不伪造百分比；后端只提供阶段时，显示阶段和不定进度即可。有真实下载字节时可显示下载进度，但不将其当成整个安装完成比例。

员工离开安装对话或切换页面不等于取消安装。返回市场可继续查看同一任务。重复点击“查看进度／继续安装”应回到原安装记录或恢复它，而非无条件创建第二次安装。

### 8.2 需要员工操作

一次只突出一个下一步。例如“请先配置视频服务”加“打开配置”，或“请登录账号”加“前往登录”。

凭证复用已有安全配置界面，不鼓励员工把 API Key 发在普通聊天里。操作完成后按钮为“继续检查”，复用已有安装进度。

员工缺少聊天模型或 Agent 不可用时，同样用清楚的前置提示“先配置对话模型”和“去配置”，不要点击安装后一直转圈。

### 8.3 失败与中断

- 用一句话说明失败原因和一个可做的动作；原始错误和日志折叠在“查看详情”。
- 已下载内容、完成步骤、员工配置及安装会话由后端保留。前端不得通过“重试”清空整个安装记录。
- 应用重启后重新读取真实状态，不把断开的事件流认定为安装失败，也不根据 localStorage 自动再次安装。
- 停止任务使用现有停止机制；停止后的状态由后端给出。不要把“停止”画成已经卸载或还原完成。
- 结果未知时显示“正在确认状态”及查看进度入口，不自动重发安装或付费媒体生成请求。

## 9. 加载开关

### 9.1 对员工的含义

开：这个应用在日常聊天中可以使用。关：保留安装内容，暂时不用它。

首次加载开关旁可用简短 tooltip：“打开后可在对话中直接使用”。无需全屏引导或反复弹窗。

### 9.2 生命周期

- 首次安装验收成功后默认开启。
- 手动关闭后，刷新目录、重启软件、升级或修复不会擅自重新开启。
- 开启只是注册可用能力目录；实际读取指令及启动 MCP 由运行时按需处理。
- 正在执行任务时关闭，显示“本轮结束后停用”，不突然中断已有生成任务。员工要中断时使用独立的停止按钮。
- 状态失效时明确显示需修复，不能仅因为保存的 enabled 为 true 就画“已加载”。
- 开关只影响当前员工的本机设置，不修改 GitHub 包文件。

## 10. 聊天输入区的“应用”入口

### 10.1 菜单布局

```text
[应用]  [当前使用：商品视频 ▾]   其他现有工具...

打开“应用”：
┌────────────────────────────────────┐
│ 应用                               │
│ [搜索已安装应用                  ] │
│ 商品视频                    [开关开]│
│ 制作商品带货短视频        当前使用  │
│ 商品套图                    [开关开]│
│ 制作电商展示图片                    │
│ 表格整理                    [开关关]│
│ 未加载                             │
│                          浏览应用市场│
└────────────────────────────────────┘
```

菜单只列已安装应用及进行中的安装记录。未安装应用通过底部“浏览应用市场”进入市场；不把整个远程商店塞进输入区。

每行名称、短用途和加载开关即可。点击已加载应用的信息区域，选择它用于当前对话；点击开关仅改变加载状态，不切换当前应用。

未加载应用的信息区域选中后，提供明确的“加载并使用”动作，不静默开启。未就绪应用显示“继续安装／修复”，不能当作已可使用。

### 10.2 选择应用后的行为

- 空白对话：展示 welcome 材料引导和 inputHint，绑定应用，不自动发送用户消息。
- 已有对话：保留现有文字草稿、附件和消息，改变后续工作使用的应用，不重新索要已经提供的材料。
- 同一轮正在生成时禁止更换当前工作应用，短提示“本次回复结束后可切换”；加载开关仍按第 9 节规则处理。
- 第一版显式选择一个当前应用。选其他应用时替换后续工作的主应用绑定，不弹出复杂组合配置；包内部可以包含多项能力。
- 用户未显式选择时，Agent 可从已加载应用目录匹配需求；当实际使用应用时，后端通知前端显示名称标签，前端不自行根据关键字猜测已绑定。
- 有显式选择时优先使用该应用；不能因另一包描述相近就无提示切换。

点击当前应用标签可查看该绑定版本的说明，并有“取消本次选择”。取消仅解除当前对话的显式指定，不关闭全局加载开关；已加载应用仍可能被普通聊天按需发现。该区别用一行短说明表达。

### 10.3 示例需求按钮

在新对话材料引导下，可把 inputHint 显示为一条可点击的示例需求。点击只填入空输入框，不自动发送、不带入示例附件。

用户已经写了草稿时隐藏该快捷示例，或改为只读展示，不能覆盖员工输入。不增设一套独立的 prompt 模板系统。

## 11. 历史记录与成品

- 工作对话继续进入现有会话列表。标题可以包含应用用途和商品信息，命名失败时使用简单默认标题，不阻止工作。
- 新包入口不建立第二套媒体结果库；沿用现有聊天消息和附件预览、下载、打开位置等能力。
- 历史会话保存当时绑定的包版本，打开后展示真实版本。市场更新不悄悄改写旧会话。
- 历史会话的包已关闭时，作品和历史内容仍可查看；继续使用该能力时提示“此应用未加载”和“加载并继续”。
- 应用已卸载或所需旧版本缺失时，保留历史材料并说明需恢复。不能直接用最新版本替代原版而不告知。
- 服务断网或生成失败时，保留需求、材料和已完成结果，通过真实工作状态提供下一步，不要求员工从头建立新对话。

## 12. 数据与后端协作边界

### 12.1 三类数据分别维护

| 数据 | 来源 | 前端职责 |
| --- | --- | --- |
| 市场发布内容 | GitHub 固定提交内的清单及示例 | 展示、分类、搜索、预览 |
| 本机安装与加载状态 | 后端持久化记录及实时状态 | 同步展示、提交用户操作 |
| 会话应用绑定 | 聊天后端及会话存储 | 展示当前使用应用，发起选择／解除请求 |

不能用远程 catalog 判断“已安装”，不能用缓存布尔值判断“已经加载成功”，也不能用输入框里有一段提示词代替持久化会话绑定。

仓库已有 [Package 格式规范](../agents/dsivio-package-format.md)、[内容目录](../../packages/catalog.json) 和 [空白模板](../../packages/_template/package.json)。这些是内容格式的事实来源，新增字段需要同步规范和 Schema。

### 12.2 建议的前端视图模型（待前后端确认）

以下为接口所需语义，具体 Tauri 命令名可另定。未实现前使用 adapter 隔离 mock，不在组件里散布 invoke 字符串。

```ts
type PackageRef = {
  id: string
  version: string
  revision: string
}

type InstallState =
  | 'not_installed' | 'installing' | 'needs_configuration'
  | 'ready' | 'failed' | 'needs_repair' | 'reconciling'

type LoadState =
  | 'unloaded' | 'loading' | 'loaded'
  | 'unloading' | 'pending_unload' | 'error'

type PackageLocalState = {
  packageId: string
  installed: PackageRef | null
  installState: InstallState
  desiredEnabled: boolean
  loadState: LoadState
  operation: null | {
    id: string
    kind: 'install' | 'update' | 'repair' | 'remove'
    stage: 'downloading' | 'configuring' | 'verifying' | 'waiting' | 'reconciling'
    target: PackageRef | null
    conversationId: string | null
  }
  installationConversationId: string | null
  update: { available: PackageRef | null; compatible: boolean }
  canUseInstalled: boolean
  allowedActions: Array<
    'install' | 'use' | 'enable_and_use' | 'enable' | 'disable'
    | 'continue' | 'configure' | 'repair' | 'update' | 'remove' | 'view_progress'
  >
  nextAction: null | {
    kind: 'open_settings' | 'authorize' | 'resume' | 'retry'
    label: string
    actionId: string
  }
  issue: null | { message: string; detail?: string }
  stateRevision: number
}
```

安装状态、加载状态、更新操作是不同维度。例如“旧版 ready + 新版 update 正在配置”可以共存，不能简单把旧版整体标为 installing。状态序号用于忽略迟到事件，以免成功后被旧事件画回失败。

市场条目还需要当前发布版本的 metadata、example、资源引用、是否下架和可安装性原因；已安装条目需要本地 metadata/example，网络不可用时仍能展示和启动。日期等字段由数据层按 Schema 验证，组件不假设每条远端内容都有效。

nextAction.actionId 由后端映射到受支持的设置或授权流程，前端不执行远端内容提供的任意命令或任意跳转代码。

### 12.3 所需 adapter 操作

| 建议操作 | 输入／输出语义 |
| --- | --- |
| `getMarketSnapshot` | 返回缓存目录、条目、加载时间和刷新错误，支持后台刷新 |
| `getPackageDetail` | 按来源版本获取清单、只读示例及受控媒体引用 |
| `getLocalPackages` | 返回所有本机记录，含下架包和未完成安装 |
| `startPackageOperation` | 类型、packageId、目标版本、请求幂等标识；返回真实 operationId、会话 ID 和本机状态 |
| `resumePackageOperation` | 按已有操作／安装记录恢复，不默认新装 |
| `setPackageEnabled` | 幂等设置目标值；返回即时确认状态，完成结果由状态事件同步 |
| `launchPackageConversation` | 创建绑定应用的新工作会话；请求幂等，返回 conversationId 与真实绑定 |
| `selectConversationPackage` | 为现有会话或聊天草稿绑定应用，保留输入和附件；发送第一条消息时落盘 |
| `clearConversationPackageSelection` | 解除显式指定，不改变全局加载偏好 |
| `performPackageNextAction` | 使用后端 nextAction 执行受支持的配置／继续流程 |
| `subscribePackageState` | 订阅安装、更新、加载状态，含 operationId 与递增 stateRevision |
| `subscribeConversationPackage` | 复用或扩展聊天事件，提供 Agent 实际选择及会话绑定变化 |

先订阅后获取快照并按版本归并，或采用后端提供的原子快照／游标机制，避免初始化期间丢事件。重连、窗口重新获得焦点或应用重启时获取快照确认状态；断线时不假装任务仍有确定进展。

请求超时不等于操作失败。先通过 operationId 或请求幂等标识查状态；前端不能自动重复安装、创建对话或提交付费任务。

### 12.4 明确由后端负责

下载校验、固定提交解析、依赖安装、真实工具注册、凭证保管、验收、加载作用域、进程生命周期、更新回滚、共享依赖所有权、会话绑定持久化和任务恢复都属于后端／Agent 运行时。

前端不能通过把 enabled 保存到 localStorage、直接拼接包文档到用户输入，或单纯调用现有插件启用 API 来宣称完成这些能力。

## 14. 视觉与可访问性

- 沿用项目现有色彩、字号、按钮和深浅主题，避免做成与聊天完全不同的网站风格。
- 内容区按可用宽度排 1–3 列卡片，不按整个屏幕宽度推断列数；侧栏和右侧面板展开后仍可用。
- 参考检查宽度为内容区 600、900、1200 px，卡片不横向溢出，详情长文本能换行。
- 不用大面积营销 Banner；员工打开后尽快看见分类和应用。
- 开关使用可访问 switch 语义，有应用名称和状态标签；状态不能仅靠颜色区别。
- 菜单支持键盘、Escape 关闭及关闭后焦点返回触发按钮；详情返回恢复合理焦点。
- 状态更新用轻量提示和适当 aria-live，避免每个进度事件都弹 toast。
- 系统减少动态效果设置下不做持续装饰动画。视频必须由用户主动播放。
- UI 英文翻译与维护者发布的包名称／示例内容分开；不假设包自带多语言字段。

## 16. 开发和联调方式

### 阶段 A：前端可独立完成

使用明确的开发 mock adapter，提供分类列表、详情、菜单、所有状态卡片及状态切换演示。不要把 mock 数据放进真实 catalog，也不要让生产构建在 API 失败后自动回落到假成功。

至少准备：未安装、已加载、未加载、安装中、待配置、安装失败、需修复、可更新、更新失败且旧版可用、等待停用、不兼容、下架但已安装等场景。使用同一份状态存储演示多入口同步。

### 阶段 B：接入真实数据与动作

对齐上述 adapter，接入真实远程目录、本机记录、安装会话、加载和聊天绑定。前端开发者需要向后端明确提出缺失接口；不要通过临时拼提示词绕开必要的状态与能力约束。

### 阶段 C：共同验证完整流程

选择维护者实际验证过的图片包和视频包各一个，验证首次安装、重新启动、直接聊天使用、失败恢复和更新。没有真实包时可以完成 UI 开发，但交付说明必须标注真实安装及媒体生成尚未验证。

## 17. 验收清单

### 浏览和说明

- [ ] 侧栏可进入独立市场，市场路径不会被识别为普通会话。
- [ ] 分类由目录驱动，新增分类无需改前端代码。
- [ ] 搜索、分类和已安装筛选组合有效；返回详情前的筛选与滚动位置保留。
- [ ] 卡片信息区打开详情，按钮与开关不会误触导航。
- [ ] 详情用短对话说明怎么用，示例有明确标识，视频不自动播放。
- [ ] 真实空目录、网络失败、搜索为空、单项内容损坏是不同状态。
- [ ] 缓存刷新失败仍能查看本机应用，正常应用不被坏条目拖垮。

### 安装与加载

- [ ] 连点安装只产生一个操作，离开页面后能回到同一安装进度。
- [ ] 进度来自真实阶段，不靠计时器把安装推进到成功。
- [ ] 待配置只突出一个下一步，补完可继续原安装。
- [ ] 所有必需验收通过后才可使用；首次成功默认加载。
- [ ] 关闭再重启后仍未加载，刷新、修复或更新不擅自开启。
- [ ] 开关失败恢复真实状态，三个入口保持一致。
- [ ] 正在执行时关闭显示待生效，结束后变为未加载。
- [ ] 更新失败保留旧版的使用入口；安装与更新版本显示准确。

### 聊天与结果

- [ ] 已加载应用在普通聊天可被实际调用，不必从市场启动。
- [ ] 聊天应用菜单可选择当前应用，保留已有草稿、附件和历史。
- [ ] 新对话显示材料引导；点击示例只填入空输入框，不自动发送。
- [ ] 市场示例消息和附件从未作为真实历史提交。
- [ ] 当前应用标签来自真实绑定，关闭／取消选择语义不同且可理解。
- [ ] 新建工作对话不携带整段安装日志，不用普通用户消息冒充隐藏工作指令。
- [ ] 历史对话保留版本；卸载、下架或关闭不导致作品丢失。
- [ ] 图片与视频结果复用现有预览、文件操作及会话列表。

### 工程与交付

- [ ] 深浅主题、窄窗口、键盘操作及长名称可用。
- [ ] 包内容未进入 Tauri 资源列表，也未作为前端静态 JSON 导入。
- [ ] mock 与生产适配层分开，真实 API 错误不会变成模拟成功。
- [ ] 路由、状态映射、重复操作、开关失败和草稿保留有针对性验证。
- [ ] 运行与改动相关的类型检查及测试，记录真实结果和未完成项。
