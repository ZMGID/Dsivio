# Dsivio 图片与视频内置功能拆分

日期：2026-09-08。状态：讨论稿，尚未实现页面或修改业务代码。

目标：在 Dsivio 侧栏新增「图片」「视频」，将 dsimage、dsvideo 的流程拆成有专用 UI 的内置功能。各功能直接调用自己的 Agent 流程和执行工具，不依赖员工安装、选择或触发 Skill。

依据：阅读两个仓库的 Skill 入口、图片全部流程指南与拍法知识、视频导演和模型提示词指南、参考分析流程、模板结构及关键执行代码。以下明确区分「现有流程」「建议 UI」和「需要补的实现」。本次没有调用生成服务，不验证供应商当前线上规格、报价或成片质量；供应商能力描述指仓库当前适配范围。

## 1. 建议的功能导航

| 模块 | 功能入口 | 现有来源 | 拆分理由 |
| --- | --- | --- | --- |
| 图片 | I1 快速出图／改图 | gen | 输入和交付简单，允许单独完成几张图 |
| 图片 | I2 按样板换货 | replace | 样图版式作为保留目标，重点是商品替换和对照审核 |
| 图片 | I3 按模板出套图 | smart | 模板规定每页目的和风格，Agent 逐商品创作 |
| 图片 | I4 从零设计套图 | design → smart | 先设计页面结构和风格，再执行套图生成 |
| 图片 | I5 多品类批量任务 | client | 管理客户共用要求、分类、每类模板和分批审核 |
| 图片 | I6 模板库与制作 | make_template、template freeze | 有独立产物，可从已有样图、空白方案或认可结果制作 |
| 视频 | V1 制作视频 | ecom-h3-video + director + 模型适配 | 接收需求到交付成片的完整工作流程 |
| 视频 | V2 创意与分镜 | video-director | 单独交付创意、剧本或分镜，不必须生成视频 |
| 视频 | V3 参考视频拆解 | video-reference-analysis | 输入已有视频，交付带证据的拆解与改编底稿 |
| 视频 | V4 视频模板库 | 两种 templates 目录 | 管理参考模板和已验证生成模板，两者用途不同 |

I2 和 I3 可共用套图工作台组件，但应有不同入口说明、方案界面和审核标准。I4 设计完成后接入 I3，不另做生成引擎。I5 组织多个 I2/I3 子任务，不复制执行逻辑。

「按模板制作视频」是 V1 的一种起点，也是 V4 的使用按钮，共用 V1 后续步骤。「H3 提示词转换」是 V1 的内部步骤和 V2 的高级导出操作，不需要占一个大众功能入口。

## 2. 图片功能逐项拆分

### I1 快速出图／改图

现有流程：[gen.md](https://github.com/ZMGID/dsimage/blob/main/skills/dsimage/guides/gen.md)。不创建套图模板或商品批次，支持带参考图生成、一条提示词出多个结果，以及基于上一版提示词继续修改。

- 输入 UI：素材拖拽区；参考图用途标记（商品／待修改图片／风格或版式）；用途选择；修改要求；画幅、图内文字及语言、生成数量、输出规格。
- 常用用途：白底图、场景图、换背景、海报、模特展示、信息图。它们作为页面内的预设，根据用途显示必要字段。
- Agent：看图、区分保留和修改内容、根据用途写提示词；修改时使用上一版，只调整用户要求的部分。
- 执行模块：解析参考素材、调用图片适配器、保存结果和提示词版本。现有 `gen` 与 `gen_image.py` 可复用。
- 结果 UI：图片网格、放大、前后对比、选中一张继续改、下载或打开目录。
- 需补：结构化参考图角色和版本关系。当前 `--n` 是同一提示词的多次生成；「三个不同创意」需要 Agent 先写三个不同方案，不能直接把数量等同于创意数。
- 边界：当前是生成式改图；精细蒙版编辑、无损抠图、图层编辑没有现成完整流程。不要仅因用途里有「换背景」就宣称具备这些能力。

### I2 按样板换货

现有流程：[replace.md](https://github.com/ZMGID/dsimage/blob/main/skills/dsimage/guides/replace.md)。模板包含示例图、每页提示词和参考图关系，执行时将当前商品带入；版式和文字保留属于生成目标，需要对照审核。

- 输入 UI：样板套图预览；选择已有模板或「用这些样图建模板」；导入文件夹／单品／单张图；SKU 素材列表。
- 素材检查 UI：每个 SKU 的正面图、背面图、品类；Agent 推荐，用户可直接纠正。缺少必要素材的商品显示具体缺项。
- 工作步骤：选模板 → 确认素材 → 必要时审核背面派生图 → 两个样品试出 → 样品审核 → 批量生成 → 交付。
- Agent：识别白底商品图、标注品类、选择有代表性的两个样品、对照母版检查文字／图标／商品外观；必要时修改对应页面的模板规则。
- 执行模块：复用 `init`、`set`、`derive`、`run --only`、`run --slot --redo`、`preview`、`deliver`。
- 结果 UI：左侧母版、右侧当前商品成图；按页比较，显示问题；「仅重做这一页」「通过样品并生成其余」。
- 修改范围 UI：明确选择「只改这个商品」或「修改模板」。单品变化对应现有 `vary` 或任务级覆盖；修改模板需要列出影响范围。
- 需补：任务级模板快照和覆盖，避免普通改单直接写坏共享模板；生成变体保留版本，不能将 `--redo` 覆盖文件直接等同于版本管理。

### I3 按模板出套图

现有流程：[smart.md](https://github.com/ZMGID/dsimage/blob/main/skills/dsimage/guides/smart.md)。模板保存整体风格、文字规则和每页 brief；Agent 根据每个商品单独写完整提示词。

- 输入 UI：模板卡片和页面结构预览；商品素材；已确认卖点／规格／配色；本轮语言、画幅和交付要求。
- 方案 UI：每页一张卡，显示目的、构图描述、图内文案、使用素材。用户修改业务描述，英文模型提示词放在高级展开区。
- Agent：观察本商品、结合 brief 创作每页方案和提示词；保持整套风格，检查人物／动作／场景是否重复，检查卖点是否有素材依据。
- 工作步骤：选模板 → 整理素材 → 为两个样品写方案 → 试出并审核 → 为其余商品写方案 → 批量生成 → 抽查与交付。
- 样品未通过时，不提前为整批所有商品写完提示词。这是原流程明确要求，能减少修改模板后的返工。
- 结果 UI：按 SKU 切换整套图片；逐页修改；样品审批；失败项补做；「以这套效果制作换货模板」。
- 需补：把 `brief.md`、`prompts.json` 中的内容转换为稳定的数据对象；对必需页面、风格约束和引用素材做校验。
- 与 I2 的区别：I2 围绕母版逐页比较；I3 围绕当前商品的页面目的和创作方案比较。smart 的示例图当前用于 Agent 看版式，不默认作为生图参考上传。

### I4 从零设计套图

现有流程：[design.md](https://github.com/ZMGID/dsimage/blob/main/skills/dsimage/guides/design.md)。先把需求落成 smart 模板，再按 I3 执行。

- 输入 UI：商品图、目标平台和市场、语言、文字由谁提供、风格参考、页数、主推色／多色策略、输出及交付要求。
- Agent：识别商品与可确认卖点，提出套图叙事顺序；产出全套风格和每页目的／文案／构图 brief。
- 方案 UI：色板和风格预览、可排序的页面卡片；可增删主图、卖点、细节、场景、规格等页面；修改后重新检查整套一致性。
- 工作步骤：填写需求 → Agent 生成套图方案 → 编辑并确认 → 校验模板 → 接 I3 试出。
- 输出：当前任务使用的设计方案及 smart 模板。原流程会将模板留下供复用；产品内建议先作为草稿，用户选择后放入共享模板库。
- 需补：模板草稿状态、页面结构编辑和确认记录。页数按模板实际 slots 读取，不固定七张或九张。
- 已填过的信息直接带入后续步骤，原 Skill 的多轮问答由页面字段完成。

### I5 多品类批量任务

现有流程：[client.md](https://github.com/ZMGID/dsimage/blob/main/skills/dsimage/guides/client.md)。适用于同一客户、多大类商品、共用一组要求，但尚未统一指定某个模板的任务。

- 输入 UI：客户／品牌、总素材目录、共用语言、风格、品牌色和生成要求。
- 分类 UI：SKU 缩略图和分类表；Agent 提议按商品大类分组，用户移动商品、合并分类或纠正类别。颜色和尺码不自动成为大类。
- 模板 UI：分类 × 模板对照表，每类选择或制作一套模板；页结构相同的子品类通过模板内品类分支处理。
- Agent：看图分类、提议每类模板、提取共用要求与单类差异、挑代表样品。
- 工作步骤：确认共用要求 → 确认分类 → 全部分类模板完成且校验通过 → 第一类两个样品 → 审核并完成该类 → 下一类。
- 执行模块：复用 `template client`、`sort`、模板校验和每类 I2/I3 任务。源目录只读，分类和成图分别存到独立目录。
- 进度 UI：按分类显示「待配模板／待样品审核／批量生成／待补图／完成」，再进入单 SKU、单页。
- 需补：客户级任务和分类子任务的结构及状态。原流程明确按类审核推进，第一版先保留这一行为；跨类并行属于后续明确修改的产品规则。
- 入口判断：用户已经指定一个模板时，即使导入大文件夹，也走 I2/I3；文件数量多本身不触发多品类流程。

### I6 模板库与制作

现有流程：[make_template.md](https://github.com/ZMGID/dsimage/blob/main/skills/dsimage/guides/make_template.md)。支持从样图创建 replace、从风格和页面目的创建 smart、从认可的 smart 结果冻结成 replace，以及客户共用规则管理。

- 模板库 UI：示例图、名称、客户／品牌、品类、用途、模式、语言、实际页数、交付规格；支持筛选、复制、导入和导出。
- 新建 UI 三个起点：「已有样图」「从风格和页面方案开始」「使用已完成的一套图」。
- 样图编辑：检查自然排序是否正确，调整每页用途、产品位置、保留文字、参考素材；固定 Logo 等进入素材区。
- 规则编辑：整体风格、文字策略、每页 brief 或保留要求、品类差异、模特变化规则、背面素材要求。
- Agent：分析每页样图、写模板规则、检查遗漏和冲突。校验器负责文件引用、占位符、品类键、交付比例等机械检查。
- 保存 UI：模板检查结果、问题定位到页面；草稿／可用状态；可接两个样品的验证流程。
- 客户规则：保持现有「模板覆盖客户共用要求」语义；新增本轮任务覆盖时独立保存，不直接修改客户规则。
- 冻结限制：当前 `freeze` 主要复制结果图、拼接提示词，并不完整保留全部背面引用和品类分支；需要 Agent 重审商品专属描述、素材映射和适用范围，再校验试出，不能标成无需检查的完成品。

## 3. 视频功能逐项拆分

### V1 制作视频

现有流程：[ecom-h3-video](https://github.com/ZMGID/dsvideo-plugin/blob/main/skills/ecom-h3-video/SKILL.md)、[MiniMax 适配](https://github.com/ZMGID/dsvideo-plugin/blob/main/skills/minimax-h3-api/SKILL.md)、[Grok 适配](https://github.com/ZMGID/dsvideo-plugin/blob/main/skills/grok-video-api/SKILL.md)。

- 起点 UI：「从需求开始」「使用视频模板」「使用已保存的分镜／参考拆解」。已提供的素材和要求随起点带入。
- 素材 UI：图片区、视频／音频参考区按所选适配器能力开放；每份素材标用途，用户选择起始帧、结束帧或商品参考，不能把这些语义混为一项。
- 需求 UI：视频用途、主要展示目标、时长、画幅、口播语言和原文、声音要求；规格由当前任务保存，不继承上一条无关视频。
- 渠道 UI：可用渠道、支持的输入、输出规格、当前估价；无法查询余额时如实显示。选择渠道与分辨率可在同一规格区完成。
- Agent：理解素材，匹配模板或生成导演方案。需求宽泛时展示三个拍法确实不同的方案卡供选择，再细化选中方案。
- 剧本 UI：目标、素材用途、镜头时间轴、动作、机位、声音、结尾；可逐段编辑并完整预览当前版本。
- 工作步骤：素材／需求／渠道规格 → 方案 → 当前剧本确认 → 模型提示词转换与参数预检 → 上传／提交 → 查询 → 下载／核对 → 成片。
- 执行模块：H3 模式选择和提示词格式转换、MiniMax/Grok 客户端、ComfyUI 准备脚本及 MCP 上传／提交／下载链路。
- 结果 UI：本地视频预览、使用规格、版本、下载状态；「按此方案再做一版」「保存为已验证模板」。后者要求用户确认成片可用并主动保存。
- 需补：完整任务持久化、剧本及付费规格确认绑定、真实媒体规格检查、结构化进度、ComfyUI 业务接口。
- 视频是模型生成完整片段。分镜时间轴用于创作和校验；任意单镜头无损替换、逐镜头渲染再自动拼片目前没有完整实现，不能直接做成已支持按钮。

### V2 创意与分镜

现有流程：[video-director](https://github.com/ZMGID/dsvideo-plugin/blob/main/skills/video-director/SKILL.md) 和 [h3-prompt-writing](https://github.com/ZMGID/dsvideo-plugin/blob/main/skills/h3-prompt-writing/SKILL.md)。

- 输入 UI：想法、商品或其他素材、已有脚本、目标、时长和画幅。只写方案时可显示待定规格，但不能让生成接口的默认值偷偷成为用户的选择。
- 创意 UI：三个不同结构／动作／节奏的方向；选择一个进一步展开。
- 分镜 UI：时间轴与镜头卡，每段分别编辑镜头目的、主体动作、相机动作、转场触发、声音和结束画面。
- Agent：确定开场与结尾，编排通常 3–6 个连续时间段；保持商品和人物可识别特征；检查时间覆盖、动作承载和对白长度。
- 输出：导演方案、分镜脚本；可导出文本、保存草稿、进入 V1。仅写方案不查询生视频余额，也不启动视频生成。
- 高级 UI：「转换模型提示词」，支持当前 H3 指南描述的文本、首帧、尾帧、首尾帧和参考模式；检查参考标签、时序与声音字段。生成入口仍受 V1 当前适配能力限制。
- 分镜图：V3 原流程明确提供图像生成动作，V2 可以复用这一动作，但这条共享调用链需要新增。分镜图本身是额外图像生成，不随文字方案自动运行。

### V3 参考视频拆解

现有流程：[video-reference-analysis](https://github.com/ZMGID/dsvideo-plugin/blob/main/skills/video-reference-analysis/SKILL.md)。这项能力包含逐镜头视觉分析、提示词、分镜图方案和参考模板，不能只做成一段视频摘要。

- 输入 UI：上传本机视频或粘贴单条可访问链接；可同时上传自己的商品素材；选择保留结构、需要替换的商品、后期文字处理要求。
- 页面主体：播放器 + 可定位时间点的镜头列表 + 所选镜头详情。关键帧和生成分镜图必须标明来源，不能混为真实视频帧。
- 分析字段：视频基础信息；原字幕／画面覆盖文字；商品原生 Logo／包装文字；声音；每个自然镜头的主体、环境、风格、构图、机位、动作、光影、时间和提示词。
- Agent：先检查工具警告并看高清帧顺序；仅对看不清的动作区间补充分析；区分观察到的事实和未验证项。
- 执行工具：现有 `video-analyzer` MCP 的 `analyze_video`，必要时 `analyze_moment`、`get_frame_burst`。
- 输出 UI：完整镜头拆解、完整视频提示词、负面提示词、通常 4–8 个代表镜头的分镜图方案。完整拆解的镜头数不能为了凑 4–8 张而删减。
- 操作：「修改拆解」「导出提示词」「生成分镜图」「保存参考模板」「用我的商品制作视频」。分析本身不自动进入生视频。
- 已有商品改编：视频提供视觉结构，用户商品提供身份和真实结构。进入 V1 时复用已确认拆解，Agent 不另起无关创意。
- 保存规则：先展示报告与保存摘要，确认当前版本后存入参考模板库。仅分析成功不能标成已经验证的生成模板。
- 需补：分析结果和关键帧的结构化持久化、可编辑报告、素材角色及时间点绑定、图像生成的连接操作。

### V4 视频模板库

现有结构：[已验证模板](https://github.com/ZMGID/dsvideo-plugin/tree/main/skills/ecom-h3-video/templates)、[参考模板](https://github.com/ZMGID/dsvideo-plugin/tree/main/skills/video-reference-analysis/templates)。

- 同一页面两个明确分类：「参考视频模板」「已验证生成模板」。模板列表展示用途、时长、画幅、素材要求、适用和不适用条件。
- 参考模板详情：来源标签、镜头证据、视觉结构、提示词、可替换内容、未验证项；使用时接 V1 的适配和确认步骤。
- 已验证模板详情：成片或预览、镜头结构、所需商品素材、替换字段、验证记录和生成渠道／规格的适用信息。
- Agent：匹配展示方式、镜头目标、素材数量和规格，品类只是辅助条件；适配当前商品，清除旧商品的颜色、功能和文案事实。
- 生成模板目前只有一个具体样例：`bedroom-ugc-product-presenter-15s`；不能把 `_template.json` 骨架计入可用模板，也不能假设已有丰富目录。
- 模板维护：新增、复制、编辑、导入导出、归档；从参考模板生成并确认成片后，创建有验证记录的生成模板，同时保留参考来源。
- 需补：模板保存在 Dsivio 的数据目录及版本库。原 Skill 的「有源码才写模板，没有源码交维护者」属于安装方式限制，内置功能不再沿用这一交互。

## 4. 视频输入能力必须随当前适配器变化

以下由仓库说明及执行代码得出，表示当前集成范围；不代表供应商所有能力或最新线上限制。

| 输入或能力 | 内置 ComfyUI 工作流 | MiniMax 客户端 | Grok 客户端 |
| --- | --- | --- | --- |
| 纯文字生成 | 已接入 | 已接入 | 已接入 |
| 图片输入语义 | 1–3 张参考图，走 Ref2VA | 首／尾帧，或参考图模式 | 单张起始图 |
| 首帧／尾帧／首尾帧专用输入 | 当前准备脚本未接入这些分支 | 已接入；不能与参考模式混用 | 只接单张起始图 |
| 视频或音频参考 | 当前工作流未接入 | 已有请求构造；需补媒体实际属性检查 | 当前客户端未接入 |
| 原任务恢复 | 需统一持久化 prompt_id 并封装查询 | status／wait／list | status／wait |
| 时长校验范围 | 准备脚本 2–15 秒 | 客户端 4–15 秒 | 客户端 1–15 秒 |

H3 写作指南覆盖的格式比本地 ComfyUI 已接好的三个分支更广。不能看到指南提到「视频续写」就把它列为现成生产功能。具体依据：`prepare_workflow.py`、`minimax_h3.py`、`grok_video.py`，见文末来源。

默认渠道可以由管理员预设，但制作页面仍需显示本次实际选择、规格和费用。渠道失败后切换、价格变化、输入超限都应该在 UI 中明确处理，不能由 Agent 静默改成另一种制作方式。

## 5. 应做成共享组件和步骤的能力

| 能力 | 放在哪些 UI 中 | 边界 |
| --- | --- | --- |
| 26 类图片拍法 | I1 用途选择、I4 页面类型与方案建议 | 是创作知识和预设，不等于 26 个已验证独立算法 |
| 商品素材整理 | I2–I5 素材检查步骤 | 保留 SKU、正／背面、品类、参考用途和确认状态 |
| 背面派生 | 需要背面素材的页面前置步骤 | 只在适用时提供；需真实背面证据的页面不能靠派生代替 |
| 图内文案／多语言 | I1、I3、I4 的字段及页面卡 | 图内语言与模型提示词语言分开；不是已有的独立翻译编辑器 |
| 样品审核 | I2、I3、I5 | 两个样品，不足两个则全部；单品通过后直接进入交付 |
| 图片质检 | 所有图片结果页 | Agent 意见与用户通过状态分开，不声称自动保证商品完全一致 |
| 尺寸和文件体积处理 | 图片结果页「交付导出」 | 生成档位与交付像素分开，保留原件，不默认放大 |
| 视频提示词转换 | V1 内部、V2 高级导出 | 模型格式可以变，已确认内容不得自行改写成新剧情 |
| 生成分镜图 | V3 操作，可复用于 V2 | 从文字分镜选代表镜头；额外调用图片生成 |
| 费用／规格确认 | V1 | 报价有来源、币种、对应规格；历史快照不能作为实时价格保证 |
| 恢复查询／重新下载 | 视频任务详情 | 原 ID 查询或原结果下载，与重新生成分开 |
| 历史和作品 | 图片、视频模块的共用入口或顶部标签 | 按任务和作品访问，不要求用户寻找聊天消息 |
| 配置和更新 | 应用／管理员设置 | 不进入普通员工的每次创作流程 |

## 6. 将原 Skill 的关键规则变成程序约束

| 原流程要求 | 建议程序和页面行为 |
| --- | --- |
| 先出两个图片样品，认可后批量 | 样品通过记录绑定素材、模板和相关参数版本；未通过时只开放样品操作 |
| 缺白图／必需背面不能继续 | 任务显示缺项，补齐对应引用后解锁受影响页面 |
| 改模板与改单品要分清 | 保存前显示修改范围；默认使用任务副本，主动发布才影响共享模板 |
| 视频剧本先展示再确认 | 保存 scriptRevision；确认按钮确认可读的当前剧本 |
| 剧本或生成规格变化，旧确认失效 | 剧本、素材映射、渠道及付费规格的相关变化使确认失效；重新预览确认 |
| 不重复提交付费视频 | 提交状态、外部任务 ID、请求摘要立即持久化；超时先查询原任务，未知提交结果单独显示 |
| 生视频与下载成功不同 | 分开显示排队、生成、下载、核对、完成；下载失败提供重新下载 |
| 参考分析不启动生成 | V3 的完成态是报告；只有用户选择制作视频才转 V1 |
| 已验证模板需要实际成片认可 | 验证记录关联已完成结果；导入或分析模板不自动升级验证状态 |
| 多人共用 ComfyUI | 内存清理先检查全局队列；清理失败独立记录，不把已成功成片改报失败 |
| 不猜商品规格和不可见结构 | 商品字段保存来源和确认状态；缺项可补素材、调整该页或去掉不成立内容 |

这些是从已有工作流中提炼的产品约束，不是本次分析要求用户逐项审批。用户点击页面上的确认按钮即可表达对应决定，不必再在聊天里重复说一遍。

## 7. 内置化前需要统一的内容

1. **视频用途冲突。** `ecom-h3-video/SKILL.md` 的总目标排除口播、UGC 和 CTA，但已验证模板恰好是「15秒卧室真人UGC商品展示」，包含口播和 CTA 动作。建议在 V1 明确「商品展示」与「创意／UGC」用途，分别加载内容约束；通用导演能力继续保留。CTA 后期叠字只有模板描述，当前仓库没有完整后期合成步骤，不能标成已实现。
2. **图片页数和默认值冲突。** 当前童装模板实际七页，部分 smart 指南仍写 H1–H9；默认套图是九页，且偏向巴西葡语、有背景的商业图。这些应属于模板属性，不成为整个应用的默认。页数从模板数据读取。
3. **产品事实和背面派生存在张力。** 通用链路允许派生背面，但童装特殊印花与箱包功能证据要求真实素材。建议模板逐页声明所需证据，区分真实上传与生成参考。生成参考不能证明商品实际具有隐藏口袋、印花或内部结构。
4. **拍法示例不宜直接作为产品保证。** 知识库包含虚拟试穿、多角度、爆炸图、对比图和认证徽章等写法，而入口又要求不编结构和卖点。迁移时把拍法作为构图知识；数量、内部、功效和认证仍需用户提供或确认，不把概念图展示成真实参数。
5. **冻结模板仍需检查。** 当前 freeze 输出偏向模板初稿，不能天然保留完整素材依赖和品类规则；UI 应有检查与试出环节。
6. **媒体核验不完整。** MiniMax 客户端说明已校验文件、大小和请求结构，但不检测视频编解码、帧率、音视频实际时长及图片尺寸；Grok 的结果检查主要看时长和可选模型字段。应用需要补媒体元数据检查，不能将「请求了某分辨率」显示成「实测已验证某分辨率」。
7. **状态和参数仍面向命令行。** 图片状态主要由已有输出文件、缺失素材和 prompts 推导；批次主要引用模板路径，尚无应用级确认、版本和完整失败历史。本轮部分参数覆盖也没有统一的业务对象。需要显式任务参数和模板快照。

## 8. 从 Skill 迁移为内置功能的职责拆分

| 原文件／内容 | 内置后的归属 | 迁移方式 |
| --- | --- | --- |
| Skill 入口的触发词、分流和引导句 | 页面入口和功能说明 | 员工点击入口就确定功能，省掉 Agent 猜路由 |
| 五问、渠道选择、规格选择 | 输入字段、选择器和缺项提示 | 页面显示有效值和来源，数据可直接修改 |
| 导演方法、商品识别、逐页创作、视觉检查 | 功能专用 Agent 指令与知识 | 按当前步骤加载相应规则和素材 |
| prompt／brief／分镜输出格式 | 类型化方案数据和校验器 | Agent 输出后校验，通过才进入下一步 |
| dsimage.py 命令组织 | 图片业务接口 | 将 init／set／run 等变为明确操作，保留有用代码逻辑 |
| core.py、gen_image.py | 内置图片执行模块 | 解开 SKILL_ROOT、模板目录和 .env 的固定依赖，注入任务配置 |
| prepare_workflow.py + 工作流资产 | 内置 ComfyUI 适配模块 | 使用内置资产副本，直接返回结构化提交信息 |
| minimax_h3.py、grok_video.py | 内置视频适配模块 | 保留请求构造、查询和下载；由任务管理提供生命周期 |
| comfy-mcp、video-analyzer | 应用管理的工具依赖 | 可以保留 MCP 协议，员工不再安装或选择插件 |
| 模板目录、要求.json | 应用模板数据和客户规则 | 导入现有模板，补草稿、版本、确认和来源字段 |
| 安装说明、环境配置、自更新脚本 | 打包、设置与更新机制 | 不作为生成 Agent 的日常执行步骤 |

流程上仍由 Agent 理解和推进创作，但调度层为每个步骤限定可用操作。比如参考分析步骤只有读取与分析工具；提示词转换步骤不能修改已经确认的剧本；生成步骤只执行已经校验的请求。

可以复用 Python 代码并随应用提供运行环境，也可以逐步迁移到 Rust。两者都不要求继续以 Skill 形式运行；关键是页面调用 Dsivio 的业务接口，代码读取应用管理的数据和配置。

## 9. 实现所需的最小数据对象

- 商品素材：SKU、品类、原图、正／背面角色、已确认规格、真实配色、来源与确认状态。
- 图片方案：模板及规则版本、每页目的、构图、文案、参考素材、提示词、单品覆盖。
- 视频方案：目标、素材映射、镜头时间段、动作、镜头、声音、结尾、剧本版本。
- 任务：功能类型、输入快照、当前步骤、样品或剧本确认、执行请求、外部任务 ID、逐项状态和错误。
- 作品：本地路径、实际媒体信息、来源任务、版本关系、用户评价和导出记录。
- 模板：模式、适用范围、所需素材、页面／镜头结构、来源、版本、验证结果。

这些对象用于让 UI 和 Agent 共享当前工作状态，不要求第一版另建完整商品管理系统。

## 10. 开发切分建议

建议先完成 I1 和一条套图流程的完整 UI，再扩展其他入口；I2 与 I3 中优先哪条取决于实际业务，但两种流程的边界先保留。I4、I5、I6 逐步复用已经完成的素材、模板和结果组件。

视频可先落 V2 的剧本编辑和 V1 的一条已验证生成链路，再接 V3 与 V4。使用参考分析、模板或自由需求开始，最终都能进入同一剧本和生成工作台。

功能清单是全量拆分，不表示第一版必须一次交付全部入口。排期前应以一份真实图片任务和一份真实视频任务检验字段及页面步骤，避免只把文档目录翻译成菜单。
