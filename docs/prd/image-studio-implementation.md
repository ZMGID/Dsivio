# 图片工作台实现

核对日期：2026-09-10，按当前工作区实现记录。

入口：主侧栏「图片」，路由 `#chat/images`。

## 已落地的使用流程

| 功能 | 原有逻辑 | 内置交互 |
| --- | --- | --- |
| 快速出图 | gen | 商品参考图 / 纯文字、26 个拍法入口、画幅、语言、清晰度、张数 → Agent 方案 → 出图 |
| 样图换货 | replace | 导入已有 template.json 与样图、选择商品正反面和款型 → 可选两款样品与人工确认，或直接批量 |
| 模板套图 | smart | 选择风格规则模板 → 每款每页独立规划 → 可选两款样品，或直接规划并生成所有商品 |
| 从零设计 | design | 商品 + 需求 → 编辑完整页面方案 → 打样；可让 Agent 提取规则模板，或将完整成图冻结为换货模板 |
| 多品类批量 | client | 商品文件夹导入 → Agent 识别分类 → 人工调整分类和模板 → 每个分类独立规划，可打样确认或直接批量 |
| 制作与试品 | workflow | 原始参考素材与要求 → 共用规则 → 可选 1–2 款试做与改进 → 沿用规则生成新增商品 |
| 模板库 | template | 内置默认 9 页 / 童装 7 页规则模板、胜利鹰男款 / 女款商务背包各 9 页样图模板；规则模板编辑、原模板目录导入导出、规则提取、完整成图冻结 |

结果页支持逐张预览、打开原图、指定图片版本修改、Agent 质检、单页重试、远程任务恢复、历史版本和交付导出。导出使用当前需求版本中每页的最新版本；重新编辑失败时不会悄悄用旧图替代。

## 实现边界

- 前端：`src/chat/images/`。按钮使用全局 Button / IconButton，下拉框使用全局 Select，表单和滚动容器复用 kv-input / kv-textarea / custom-scrollbar。主题来自全局 kv 语义变量，没有独立配色。
- IPC：统一在 `src/api/tauri.ts`；路由同时接入 Chat、Sidebar、chatRoutes 和 useChatRouting。
- 后端：`src-tauri/src/image_studio/`。类型、持久化、Agent 步骤、图片接口和命令分开组织。
- Agent 复用现有 `run_agent_loop`，使用专门的无工具 Host 做商品识别、画面规划、规则提取和质检。不发现、安装或激活 Skill，不依赖 Python。
- 内置聊天通过 `studio` 原生工具调用相同的 `image_studio_*` 服务。另保留 `resources/skills/dsimage` 的规则与脚本，供没有宿主工具的外部 CLI 使用；独立脚本依赖 Python，页面及内置聊天的原生图片执行不依赖 Python。
- 图片生成使用 Rust 原生适配器：OpenAI 标准、Grok、dsimage Gemini responseFormat、Gemini Chat 兼容、返回 task_id 的异步网关。沿用应用供应商的地址、密钥、代理选择和请求头配置。
- 模板和拍法说明来自 ZMGID/dsimage，作为应用资源编译进入客户端；保留 MIT 署名。新任务引用模板快照，后续编辑模板不改写已有任务。
- 模板核对版本：`bc83321d19cf51f694b1aa06efbc4cdcc7effd34`。两套背包的 18 张参考图及男款 logo / 背面辅助图完整打包；默认与童装规则模板上游没有参考图。卡片只预览前 3 页，点击可翻阅全部页面。内置素材在桌面端落到工作台模板目录，供生成、导出和保存副本使用，浏览器预览使用同源打包图片。上游「童装图片」客户分类目录不作为独立通用模板导入。

## 状态与批量规则

每个任务保存需求修订号、商品、模板快照、逐页方案、图片版本、远程任务编号与分类确认状态。输入修改后失效旧方案和样品确认；原图仍保留在历史版本中。界面草稿包含任务修订号，重新进入时不会覆盖另一窗口更新后的任务。

每个分类可取前两款商品打样；不足两款则使用全部商品。选择确认试品时，后台要求试品的全部计划页面在当前需求版本成功。直接批量不依赖样品确认；制作与试品的 `workflow_produce` 也允许在规则有效时直接生成新增商品。单页修改会撤回相关试品确认，规则变更要求重新规划；已有未解决远程任务仍需先恢复查询。Agent 质检只提供意见，不代替用户确认。

图片提交不自动重试。异步接口返回任务编号后立即保存，后续恢复只查询原任务。没有任务编号的连接中断会提示先检查供应商记录，再手动重试。停止会等待已提交的同步图片保存，异步图片可保留任务编号后停止查询。应用重启会把残留执行态恢复为可处理的中断态。

快速出图、样品和批量出图共用最多 9 张的并发队列，异步任务从提交到查询完成持续占用一个名额。某张完成后立即保存并补进下一张，结果卡片仍按方案顺序排列；某张失败不会中断其他页面。停止后不再提交排队页，已提交的同步请求收尾保存，异步任务保留编号供恢复。任务状态由一个协调器写入，避免并发覆盖结果或远程编号。

素材复制到应用数据目录 `image-studio`，使用内部相对路径。模板引用需位于导入模板目录内。成图默认保存到系统图片目录 `Dsivio/Images`，也可指定输出根目录；首次保存固定任务目录，后续改名或修改默认目录不移动已有产物。原图和每次编辑均生成新文件；交付导出创建独立文件夹，可等比缩放、补白和限制 JPG 大小。详见[保存目录规范](image-studio-folder-convention.md)。

## 内置 Skill 与页面互通

- 两个入口都使用 `image-studio/templates/<目录>/template.json` 及相邻参考图。`record.json` 仅维护页面 ID，读模板时标准文件优先；旧页面模板自动补出标准文件。聊天新增模板按目录生成稳定 ID，不要求调用 IPC 或手动导入。
- 模板库切回窗口时刷新，打开期间每 3 秒刷新；刷新列表不会覆盖当前未保存的商品需求。模板名称取 JSON 的 name，不把页面 UUID 当作用户可见名称。
- 内置模板启动时发布到共享目录；修改内置模板需创建副本，避免应用更新覆盖。页面复制与 Skill 的 `studio copy-template` 都保留全部素材，并给副本独立身份。
- Skill 每次生图从图片设置和供应商设置读取供应商、选中 API key、模型、协议、自定义头及系统代理开关。runtime.json 仅保存设置文件位置，不导出密钥。OAuth-only 供应商无法由 Python 读取系统凭据，需 API key。
- 内置 Skill 的 setup/update 命令只引导到应用设置和应用更新，避免维护第二份配置或覆盖打包资源。原 skill 的规则说明、批次脚本、参考资料保留。
- **任务边界**：内置聊天与页面已经通过宿主 `studio` 工具共用任务、草稿和执行服务。没有该工具的外部 CLI 才沿用独立脚本；其 `_dsimage/batch.json` 与页面 `tasks/*.json` 不同，不能相互覆盖。详见[聊天与工作台互通](../studio-chat-sync.md)。

## 配置与当前限制

图片设置是这台客户端内所有图片功能的共用配置，密钥由现有供应商设置维护。公司级远程配置分发、账户权限和远程模板更新服务尚未建设；不能将本版描述为已有后台统一管理。

本版按最多 9 张并发执行图片任务。现成模板的槽位、正反面引用、款型分支和换货变量已接入；派生背面和模板层批量修正尚未迁入。需要背面的页面要求用户提供真实背面，避免生成未知结构。上游的降并发自动重试尚未迁入，页面保留逐页错误与手动重试，连接中断和已有远程编号不会自动重新下单。

已有模板可以直接导入包含 template.json 和图片的文件夹。仅有一堆样图时，当前需先整理成模板目录；模板编辑器支持创建规则模板。

## 任务管理与输入检查

任务库复用 `src/chat/studio/` 的筛选、搜索、钉住和删除。删除会清理可确认归属的专属文件，同时保护原始导入素材和其他任务／草稿／模板引用；不会删除运行中任务。后端锁、目录归属检查与记录最后删除的顺序见 `src-tauri/src/studio/library.rs`。

`imageValidation.ts` 在前端检查生成配置、协议、画幅、清晰度和数量；后台 `engine.rs` 等仍执行最终校验。修改配置不能让旧任务绕过后端检查。
