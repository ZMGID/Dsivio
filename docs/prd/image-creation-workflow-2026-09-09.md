# 图片制作与试品流程

用户需要在同一个任务中完成：给商品图或成套样图和要求 → 制作可复用规则 → 用其他商品试做 → 反馈修正规则并再次试做 → 确认效果 → 持续添加商品生成。实现入口为图片工作台的「制作与试品」。

参考本地 dsimage 源码和 `make_template.md`、`replace.md`、`smart.md`。对照仓库版本为 `bc83321d19cf51f694b1aa06efbc4cdcc7effd34`。参考文档用于明确产品行为，未执行文档中的生图指令，也未使用浏览器。

## 操作流程

1. 选择「商品图起步」或「成套样图起步」，导入原始素材，填写制作要求、平台、语言、比例和清晰度。商品图起步可以指定整套页数；成套样图按素材顺序逐页制作，可调整顺序。
2. 「开始制作」由看图 Agent 生成统一风格、文案规则和每页构图/换品说明。规则保存为任务快照，并进入共用模板库。页面提供可读说明和手动编辑入口。
3. 在同一任务添加其他商品，每款可包含正面、真实背面、细节图和已确认的商品信息。多款可按文件夹导入。选择 1–2 款后「生成所选试品」，自动按当前规则规划并并发生图。
4. 对照原始参考和结果。「对共用规则的修改意见」会让 Agent 同时查看原始参考、试品商品、生成图片和已有修改记录，修改后续商品共用的规则，并自动重新生成已有试品。手动编辑规则也走相同的版本与试品流程。
5. 所选试品的全部页面成功后，由用户点击「试品满意，确认这版」。继续添加商品后「生成新增商品」，沿用已确认的规则并跳过已经尝试过的页面。
6. 「查看 / 只改这张」沿用单图编辑；此操作只产生图片版本。失败页可重试，已有远程编号可恢复查询。修改记录和历史图片保留在任务中。保存后可从最近任务继续；导出使用原有交付面板。

## 状态与生成约束

- `Brief.workflowInput` 保存独立的制作素材和模式；试品/后续商品仍使用 `Brief.products`。
- `Task.workflow` 保存规则版本、规则是否匹配当前要求、已确认版本、试品 IDs，以及包含完整规则快照的修改记录。旧任务兼容这些可选字段。
- 修改共用规则会增加版本，清空旧方案和确认状态，保留旧图，重新规划所选试品。当前规则优先于初始制作要求，避免初始要求覆盖后续反馈。
- 修改原始素材或输出要求需要更新制作。修改试品素材/信息会撤回确认；修改其他商品只使该商品的方案和结果失效。
- 追加商品或保存名称沿用未变商品的方案、图片和确认状态；更新这些图片记录的任务修订号，不复制整批记录。真正发生规则/商品变化的旧图继续作为历史保存。
- 确认依据每个试品的每个规则槽位的最新成功结果。旧规则的图片和失败修改之前的成功图不能用于确认。
- 共用规则的反馈编辑限制在风格、文案和每页文字规则；素材路径、页面身份、顺序、输出规格不能被模型悄悄替换。重排页面需修改制作要求后更新制作。
- 生图调用复用 9 路并发调度器。已保存远程编号不会自动重复提交；未完成远程任务需先恢复查询，再替换规则或商品素材。
- 规则版本、试品状态和任务存储相连；无需在快速出图、模板库、套图和批量页面间搬运中间结果。

## 验证与范围

前端组件测试覆盖创建入口、制作素材与试品分开导入、保存同一任务后追加商品、选择试品、反馈动作、规则编辑、确认门槛、历史图片及远程恢复。Rust 测试覆盖版本失效、重复保存、已确认规则复用、新增商品筛选、失败最新结果、远程记录、旧任务兼容与规则路径约束；并发调度器测试同时回归。

验证使用本地组件测试、编译、模拟供应商及状态测试。没有使用浏览器，也没有调用真实付费图片 API；实际供应商的图像质量仍需要用商品图试做检查。

本次结果：图片前端 27 项测试通过，Rust 图片模块 25 项测试通过，修改的前端文件 ESLint 通过，Vite 生产构建通过。全量 TypeScript 检查仍报既有 `Kivio` / `Dskivio` i18n 字段命名错误（自动化、上下文提示和第三方应用页面），本次图片文件没有新增类型错误。

暂未引入 dsimage 的全部外围能力：自动派生背面、限流动态退避、按部分槽位修订、模板交付参数完整映射、`batch.json` 与页面任务双向同步。当前实现覆盖用户提出的制作—试品—修正—持续生成流程。
