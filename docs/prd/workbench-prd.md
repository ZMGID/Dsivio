## Problem Statement

工作台侧栏共 39 个功能，约一半只有 UI 外壳。若每页各自实现提交、轮询、记录和平台调用，规则会散落在几十处，无法维护。已有的 `run_ai_task`（AI）和 `media_generation` + `dsivio media`（生图生视频）证明了「一种能力一套实现」可行，但本地媒体处理、电商平台业务接口和产物记录还没有统一底座。

## 完成定义

工作台侧栏里的每一项功能都接通并能实际使用：从输入到产物（或平台结果）走真实链路，在真实 App 中验收过。没有只有外壳的页面。

## Solution

三层结构：

```
功能页            每页只有：表单 + build*Request 纯函数 + 结果展示
  ▼
能力层            AI 写作分析 │ 媒体生成与处理 │ 电商平台 │ 产物记录
  │               每种能力一套实现，三个入口：工作台页面 / 对话 Agent 工具 / dsivio 命令行
  ▼
基础设施          模型池、密钥、本机存储、任务恢复
```

先补齐能力层底座，再逐页组装功能。功能页不得自建提交、轮询、任务列表或平台调用。

### 能力层

| 能力 | 现状 | 本期新增 |
|---|---|---|
| AI 写作分析 | 已有：`run_ai_task`（ADR 0008） | 只补 `dsivio ai` 命令行入口 |
| 生图、生视频 | 已有：`media_generation`，三入口齐全（ADR 0009） | 不改 |
| 本地媒体处理（转写、字幕烧录、裁剪、拼接、配乐） | ffmpeg 与本地 ASR 已打包，但没有任务化 | 作为本地供应商并入 `media_generation`（同 ComfyUI），共用任务记录、恢复、`MediaTaskList`；在 ADR 0009 补充说明，不另建通用 Job |
| 电商平台 | 只有授权和店铺信息 | 业务接口（商品、上架、订单、店铺数据），见下节 |
| 产物记录 | 只有媒体任务有记录 | 文案等非媒体产出也带 `origin` 记录，统一进「图片视频库」 |

### 三入口规范

- 一套实现放在 Rust 的一个模块；任务状态只在该模块修改；提交、回执、恢复、防重复提交规则只写一份。
- 入口只做转接：页面经 Tauri 命令 + 前端 hook；对话经 Agent 工具；插件 / Skill / 外部 Agent 经 `dsivio <能力>`。
- 范围：工作台入口随每个功能必做；对话工具与命令行入口按能力做——本地处理、电商平台补齐两者，AI 只补命令行（对话本身就是 AI）。不要求每个功能页单独提供对话入口。
- 统一结果分类：成功 / 被拒（未扣费，可重试）/ 失败 / 结果不确定（只能查询，不能重交）/ 已取消，沿用 `dsivio media` 退出码约定。

### 两种功能模板

生成类功能只有两种形状，与 `run_ai_task` 的 `once | agent` 对应（ADR 0008）。每个功能页套用其一，不自创第三种流程。

**一步（简单）**：填表 → 出结果。
- 可选 AI 帮写一次提示词（`once`），然后一次提交到媒体生成或处理，结果进任务列表。
- 失败直接重试；没有中间状态需要保存。
- 现成样板：主图生成。

**多步（复杂）**：方案 → 确认 → 执行。
- AI 先出方案（`agent`，可读图、读视频、多轮分析），例如一套图的每页安排、视频的镜头脚本、复刻的改写方案。
- 用户查看、修改、确认方案；方案随项目保存，离开再回来不丢。
- 按方案逐项提交媒体任务；每项独立显示进度，部分失败只重做失败项，不整套重来。
- 方案确认前不产生付费生成；确认后改方案不影响已提交的任务。
- 现成样板：套图设计、视频复刻（`ImageProjectWorkspace` / `VideoProjectWorkspace`）。新的多步功能接入这套项目流程，不另写。

非生成类页面（库、记录、模板、账号、平台数据）不属于这两种，按普通列表 / 表单页处理。

### 电商平台层

每个平台独立实现，对外是一套统一接口和统一的商品、上架、店铺指标概念；平台不支持的能力明确告知，页面据此显示。具体接口、类目映射、测试方式由实施者按各平台官方文档调研决定。

用户可见效果：

- **自动化上架**：商品信息（标题、价格、SKU 等）在上架表单中填写，图片和文案可从产物库带入 → 选一家或多家店 → 按平台填类目和属性 → 提交。每次上架一条记录，显示审核中 / 成功 / 被拒及原因；失败可修改后重交，已成功的不会重复上架。
- **店铺概览**：按今天 / 昨天 / 7 天 / 30 天看每家店的成交额、订单、退款等指标；平台不开放的指标显示「平台不支持」，不填 0。
- **上架检查**：补齐境外 4 平台的标题、图片等规则（现有 `listingCheck.ts` 只覆盖国内平台）。
- **对话**：可直接要求「把这几张图上架到我的虾皮店」，走同一实现。

### 套图：工作台与 dsimage 共用契约

- 工作台侧栏里的套图功能（图片复刻、模板套图、套图设计、批量套图）都在工作台完整可用，沿用现有项目流程。
- 对话中的 dsimage Skill 保留自己的流程，另负责侧栏没有的「甲方大单」；工作台的套图页提供「用对话做」入口，需要来回讨论时转到对话。
- 两边共用两份契约，不共用代码：模板格式只有一份 JSON Schema（放 `docs/schemas/`）和一组共用示例模板，Rust 与 Python 测试都校验它；出图都走 `media_generation`（工作台直接调用，dsimage 经 `dsivio media`）。

## 约束

- 只有 UI、尚未接通的页面不得假装成功：提交按钮禁用或明确标注未接通。
- 商品档案不作为共用数据来源，其他页面不依赖它。
- 功能注册只改 `registry.ts`；不改 `Chat.tsx`、路由词表、侧栏。
- UI 复用全局组件（规范 §1）；页面不直接 `invoke`。

## 范围外

- 平台类目的自动映射。
- 已接通页面的功能扩展与视觉重设计（表中列出的「用对话做」入口与模板 Schema 除外）。
- dsimage Skill 内部流程的改写（只做模板 Schema 共用与工作台的「用对话做」入口）。

## 分期与验收

| 期 | 内容 | 完成标准 |
|---|---|---|
| P0 | 在真实 App 中验收全部已接通的生成页（先主图生成、套图设计两个样板）及工作流 | 样板先确认可用，新页面才照样板复制；问题修复或记入任务清单 |
| P1 底座 | 补 ADR（电商平台层、本地处理并入媒体任务、三入口规范）；电商平台统一接口 + 首个平台（由实施者按文档与测试条件选择）；本地处理首项（转写出字幕）；产物记录；`dsivio ai` | 各能力三入口可用；无真实店铺时以录制响应验证 |
| P2 电商与库 | 其余 3 个境外平台；店铺概览、自动化上架、上架检查；图片视频库、角色模板、使用记录 | 页面接真实数据；平台不支持的指标如实显示 |
| P3 生成页 | 种草文章、视频字幕处理；图文带货、详情页、真人带货、短剧带货、产品视频编辑；套图模板 Schema 与「用对话做」入口 | 每页套用一步或多步模板，不新增流程 |
| P4 发布 | 视频发布 4 页（内容平台） | 同电商平台层模式 |
| P5 补全 | 国内 5 个电商平台的业务接口（接入同一平台层）；商品档案 | 侧栏全部功能达到「完成定义」 |

每期通用验收：
- 前端 lint / typecheck / architecture / vitest 与 cargo test 全绿；每页有请求组装、失败、重试、迟到结果、离开再回来的测试。
- 真实 App 验收单独记录；涉及付费生成或真实店铺的验收须先征得负责人同意，不以单元测试代替。
- 每期结束更新 [Workbench 任务清单](../workbench-tasks.md)。
