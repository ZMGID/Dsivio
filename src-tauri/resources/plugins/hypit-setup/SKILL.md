# Hypit setup

Hypit's Skill is installed in `~/.kivio/skills/hypit`. Check what actually works, fill in what is missing, and check again.

1. Confirm the current chat can load `hypit` and `hypit-setup` and that the files in `~/.kivio/skills/hypit` are readable. If a market-owned Skill is missing, use the marketplace install/repair action; do not copy it into `~/.agents/skills`.
2. Hypit conversations open in the dedicated Hypit project, so the working directory is its root, shared by every Hypit conversation. Run `hypit runtime init` there for the shared Runtime Profile (`hypit.runtime.json`); it creates and selects the Profile, and an existing one is kept. Keep each video in its own subdirectory; do not create a Profile per conversation. `hypit runtime init` adds a `hypihub.default` Endpoint that needs a HypiHub login; Dsivio does not use it, so remove that Endpoint (and any binding naming it) from `hypit.runtime.json`. Do not ask the user to log in to HypiHub.
3. Make sure the `hypit` executable works in the Dsivio chat environment. If missing, install it following the [official README](https://github.com/hypit-ai/hypit).
4. Connect Hypit's image and video generation to Dsivio. Dsivio already holds the models the user enabled under Settings > 媒体创作 and calls the services itself, so Hypit needs **no URL, no key and no vendor protocol**. Dsivio ships a ready, tested Hypit adapter next to this Skill in `~/.kivio/skills/hypit-setup/adapter/`; do not write your own Provider, and read [references/dsivio.md](references/dsivio.md) only for the `dsivio media` command it calls.

   1. Run `dsivio media models`. If it lists no image or no video model, ask the user to enable models in Settings > 媒体创作 and stop.
   2. Make the project a small npm workspace so the adapter can be installed: the project `package.json` needs `"private": true`, `"type": "module"`, `"workspaces": ["packages/*"]` and `@hypit/hypit` in `devDependencies` (use the version `hypit --version` prints; the adapter imports `@hypit/hypit/endpoint-kit` from it and carries no dependencies of its own). Copy `~/.kivio/skills/hypit-setup/adapter/` to `packages/dsivio-hypit-provider` in the project (replace an older copy: it is Dsivio-owned code and is overwritten on every setup), then run `npm install` in the project root so `@dsivio/hypit-provider` resolves.
   3. In `hypit.runtime.json` add the Endpoint `"dsivio.media": { "use": "@dsivio/hypit-provider" }` with **no `config`, no `baseUrl` and no `apiKey`**, and **no `bindings` for it**: Hypit uses a single compatible Endpoint without one, and the adapter decides on its own which Hypit models it serves from the models enabled in Dsivio. Remove any Endpoint, binding or package from an earlier setup that carries a URL or key or calls a vendor API directly (for example `provider-dsivio-*`, `@kivio/provider-dsivio`, or a binding that names `dsivio.media` for a model it does not offer). Then select the Profile with `hypit runtime use hypit.runtime.json` (the Profile file is required; it is a no-op when already selected).
   4. Run `hypit doctor` and read the `DSIVIO_*` lines. `DSIVIO_MEDIA_READY` lists each Hypit model and the Dsivio model that serves it (for example `seedance-2.5 <- provider/doubao-seedance-2-5-260628`). `DSIVIO_MODEL_NOT_IN_HYPIT` names an enabled Dsivio model Hypit has no model for; `DSIVIO_MODEL_UNKNOWN` says Dsivio has no facts about a model, so Hypit sends only its prompt. `DSIVIO_NO_MODEL` / `DSIVIO_UNAVAILABLE` mean no image or video model is enabled or Dsivio is not running: tell the user, do not work around it. Report these lines to the user as they are.
   5. Which Dsivio model serves a Hypit model is decided in Dsivio: the models enabled under Settings > 媒体创作, in the order shown there (the first one that fits wins). The adapter reads that list when the Hypit Runtime loads it; after a change in Dsivio, run `hypit runtime down` then `hypit runtime up` so the next `hypit doctor` and `hypit build` see it. To pin a model, add `"imageModel"` / `"videoModel"` to the Endpoint config with an `id` from `dsivio media models`. A pin restricts that media kind to the corresponding Hypit model, using the pinned model's capabilities for planning and submission. `DSIVIO_MODEL_PIN_INVALID` means the pin is not enabled for that media kind or has no compatible Hypit model; fix or remove the pin instead of falling back to another model.

   The adapter offers only what the model chosen in Dsivio can carry: first and last frames, reference images, videos and audio, audio on or off, duration, resolution and aspect ratio, each checked against that model's own limits before anything is submitted. A request the model cannot carry is refused in `hypit plan` with the model and the reason. Hypit models that need settings Dsivio cannot carry (Seedream: quality bands, output format, safety check; Nano Banana: output format) are not offered, and neither is web search. Exit code 5 from `dsivio media` means the submission may have been accepted: never submit it again. `DSIVIO_RECEIPT_LOST` means the provider accepted a task and then stopped returning it (it may have been charged): give the user the receipt and let them check with the provider before generating again. Do not read Dsivio's settings or keys, do not call vendor APIs, and do not probe services. If a needed detail is not in the reference document, report what is missing.
5. **Verify with a real generation** each model `hypit doctor` reported as served: one image and one video, as small and cheap as the model allows (shortest duration, lowest resolution, a simple prompt). The user has agreed to this test cost; do not ask again. Setup is done only when the CLI runs, the check passes, and the image and the video are actually generated. If something fails, report which model and the error, then stop; do not keep retrying or probing.

When all of this succeeds (including the real image and video), append ` [setup completed once]` once to the `description` line of the installed `~/.kivio/skills/hypit-setup/SKILL.md` and leave the rest unchanged. Do not mark an incomplete setup. The marker only records a past success: rerun setup when asked or when the environment changes, without appending it again.
