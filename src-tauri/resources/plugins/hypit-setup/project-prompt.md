This project is Hypit's dedicated project. Its image and video generation is connected to Dsivio, so do not ask the user for a service URL, an API key or a HypiHub login.

- `hypit.runtime.json` has the Endpoint `dsivio.media` (package `@dsivio/hypit-provider`, copied to `packages/dsivio-hypit-provider`). It carries no `baseUrl` and no key: it runs the `dsivio media` command, and Dsivio makes the requests with the models the user enabled under Settings > 媒体创作. There is no binding to maintain.
- Which Hypit models are available follows the models enabled in Dsivio. Run `hypit doctor` and read the `DSIVIO_*` lines: `DSIVIO_MEDIA_READY` shows each Hypit model and the Dsivio model that serves it. Run `dsivio media models` to see every enabled model with its `capabilities` (first/last frame, reference image/video/audio limits, audio switch, durations, resolutions, ratios). Look there before choosing a model or writing a request; a model with `known: false` takes a prompt only.
- What a request can contain depends on the model that serves it. `hypit plan` refuses what that model cannot carry and names the model and the reason: change the request, or ask the user to enable or reorder models under Settings > 媒体创作 (the order is the priority); after such a change run `hypit runtime down` and `hypit runtime up`. Hypit models needing settings Dsivio cannot carry (Seedream, Nano Banana) and web search are not offered.
- Generation is paid. If `dsivio media` exits with 5 (the submission may have been accepted), never submit that request again; query it with `dsivio media status <id>`. Exit 6 means Dsivio is not running: ask the user to open it; running tasks continue once it is open. Exit 2 or 3 means nothing was charged. `DSIVIO_RECEIPT_LOST` means the provider accepted the task and then lost it: give the user the receipt to check with the provider instead of generating again.
- `hypit doctor` may report `RUNTIME_CREDENTIAL_MISSING` for `hypihub.default`; that Endpoint is not used here. Remove it from `hypit.runtime.json` (the `hypit-setup` Skill does this) rather than logging in to HypiHub.
- If generation is missing, fails, or `hypit doctor` reports a `DSIVIO_*` error, load the `hypit-setup` Skill and follow it instead of configuring another provider.
