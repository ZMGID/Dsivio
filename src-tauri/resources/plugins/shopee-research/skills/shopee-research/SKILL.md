# 虾皮商品调研

结合图文与常识判断商品特点，按用户指定范围调研，交付简洁的带图调研表；未指定数量时选三类代表竞品。

## 工具与配置

- 首次使用、配置不完整或采集时发现环境失效，加载 `shopee-research-setup` 补齐后继续。
- 每次启动读取 `~/.kivio/shopee-research/config.json` 的浏览器、窗口标识、站点和结果目录，复用已准备好的浏览器窗口，直接调研。本次指定优先，要求记住时更新默认配置。旧 `shopee-research.config-path.txt` 指向的配置可迁入此处。
- 加载 `cua-driver`，网页统一用CUA原生窗口操作，沿用现有标签，必要时在同一窗口开标签；本地整理和出表使用脚本。
- 报表默认按商品和调研目标选择字段，兼容旧配置`default-nine-columns`；用户也可通过`reportFormat`指定模板路径。
- 每次创建 `<日期>-<商品>-<站点>` 任务目录，同名追加序号。`progress.json` 保存当前阶段、候选ID、已完成项、来源文件和阶段起止时间；续跑复用已采信息，更新过时结论。

## 访问节奏

- 沿用实际使用浏览器的配置和登录会话；保留搜索页及需要的数据列表／商品页，串行采集。同一浏览器的多个调研任务共用节奏。
- 每批最多7款；打开商品、切换规格和图库等网页操作之间随机间隔几秒（如2–6秒），结合图文阅读时间调整。页面加载与SKU价格刷新以可见状态稳定为准。
- 每批结束暂停网页操作，在本地检查数据完整性、价格与销售单位、图片对应及重复样本；简短分析已覆盖的价位、类型和销量分布，确定下一批应补的商品类型或关键词，写入进度后再继续。批间以分析完成为准。
- 一款一次收齐：优先复用已保存的全文、截图和规格，需要核价时确认一个目标SKU即可；文字和图片足够判断时直接整理。虾多拉只用已有可见结果，需要时才展开查询。
- 遇到`/verify/traffic/`或临时访问受限，保存数据、截图、待采链接及`progress.json.access`（`status: cooling_down`、原因、重开时间、恢复次数），暂停采集并正常关闭本次使用的浏览器，记录浏览器名称和窗口／账号标识并保留原配置与会话；有未保存内容提示时停下交用户处理。默认冷却5分钟，期间整理本地数据，再重开原来的浏览器及对应账号窗口，先打开当前站点的Shopee首页（如巴西站`https://shopee.com.br/`），检查首页是否正常可浏览（需要登录的功能再确认会话）；正常后再回到搜索页，接着未完成项；本次自动恢复最多一次，仍受限则保持任务暂停并告知用户。冷却不算任务失败。验证码或明确账号限制交用户处理后续跑；普通加载失败最多重试一次。

## 1. 搜索并初筛

根据产品图片特征和图片文字生成适合当地电商的标题及搜索关键词，记录关键词、排序、时间和时区。默认采集当前结果页的一批商品。用户指定数量时持续补页或调整关键词，收集足量有效商品；明确受阻时保存已完成项和缺口。

搜索后使用虾多拉的`View Product Details`打开相关商品数据列表，批量读取价格、商品ID、卖家、上架时间、累计及近30天销量／GMV；这是虾多拉数据列表，Shopee商品详情只在缺关键商品信息时打开。搜索页卡片已经完整显示所需指标时可以直接复用。支持导出或`Copy Link`时直接使用并保留原文件；可访问文本被截断时用CUA截图读取可见字段。

先根据商品和调研目标选择真正影响比较的字段，不固定品类模板或列数。尺寸、材质、功能、容量、款式、套装内容等按比较价值取舍；例如服装可能需要面料尺码，电器可能需要功率容量，婴儿车可能需要功能和套装区别。无助于本次判断的字段整列省略。列表图文和虾多拉数据足够就直接整理入表，保留Pix／优惠券及起价等条件；只有销售单位、套装内容、价格适用款式等关键比较信息不清楚时才进详情，已采内容从本地复用。

将商品ID、标题、链接、数字价格、`salesRaw`（销量原文）、`period`（销量期间）、`salesSource`（Shopee／虾多拉）、`gmv`（数字金额）、`gmvPeriod`、`currency`及`included`（是否相关）存入`samples.json`。按品类、功能与形态排除无关商品；GMV只记录实际可见数据，缺失时省略。

用户指定数量时保留足量相关商品逐款调研；默认代表品模式运行 `dsivio python scripts/select_candidates.py <任务目录>/samples.json <任务目录>/selected.json`（退出码 127 时改用`~/.kivio/shopee-research/runtime/runtime.json`记录的`python`）。脚本按商品ID去重，在同一币种与销量期间内选最高、居中和最低标价且有销量的候选，重复命中合并标签。`40mil+`、`10万+`等按显示量级参与比较，主表保留原文；同量级以商品ID稳定排序，摘要简注“按页面显示销量量级筛选”。只有近30天数据时统一使用该期间。GMV辅助判断同类商品的销售规模和价格定位，比较时统一币种与期间；销量仍决定三类代表品，不用当前SKU价乘历史销量代替GMV。

## 2. 每个候选一次整理完整

每个商品连续完成以下内容，再切下一个：

1. 从列表图文判断商品类型、功能、款式及销售单位。不同配置和套装按可比口径比较，赠品或配件排除。价格适用范围清楚即可使用，优惠条件写入摘要或分析；需要比较指定SKU时才进详情，选全规格组后复读刷新后的最终价。
2. 图片和文字结合判断，只采本品类需要的字段；需要补关键内容时一次读完属性和描述。可见外形、功能可以判断，厘米数值和成分比例按明确标注填写；缺少非关键尺寸不影响入选。
3. 列表中清晰的静态商品图可直接用CUA截图并裁剪；需要详情图时选图库第二张静态图，若第二项是视频则选相邻静态图。图片应对应商品及比较款式，以商品ID保存。
4. 将整理结果写入 `report.json` 并更新进度。已采信息先在本地查找；价格、销售单位或套餐数量确实无法判断的少数商品替换掉。原始冲突留在任务数据。

虾多拉指标区分商品级与SKU级，商品累计或近30天销量不能当成单SKU销量。GMV随关联商品数据一起保存，用于批间分析和选品判断；库存明细和其他期间指标按需补充。实际SKU价改变最低价比较时更新 `samples.json` 重筛，已完成的候选直接复用。

## 3. 生成与交付

读取 [报表规范](references/report-format.md)，按品类选定字段后运行随附出表脚本。一次完成排版、图片压缩、嵌入、链接和文件检查；只交付一份XLSX、一个工作表：简短摘要、一段分析、按品类精简的竞品表。需要比较套餐价时，在本地计算每单位价格用于分析；GMV有助于判断时简写进顶部分析，原始指标留在任务目录。

检查图片对应、文字布局、价格及单位，交付时简述本次样本的结论。生成脚本通过最终文件检查才记出表完成；软件兼容性沿用已验证格式，格式变更时再实测。流程受阻或用户接管时保存进度，续跑接着未完成项。
